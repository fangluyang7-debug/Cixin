## 首阶段行为

`ShoppingTaskService.search` 对 `text_encode` 生成兼容画像。如果只存在本机候选，模式为 `LOCAL_ONLY`。调用方可通过 `setShadowPlacement` 提供最多三台 `MOCK` 远端设备与链路；这时模式为 `SHADOW`。策略将每台设备的预计传输、排队、模型加载和计算时间相加，并为远端加不确定性余量。远端若在质量、隐私、后端、内存、模型、在线、信任和字段有效期检查中失败，则不会产生建议。

`PlacementDecision.actualDeviceId` 始终为本机，`dispatchAllowed` 始终为 `false`。`suggestedDeviceId` 只是模拟建议，不会改变应用的真实执行器。现有购物模板 `LOCAL_ONLY` 且 `networkAllowed=false`，因此它不会为真实搜索建议远端；要检验远端评分，可使用独立、明确允许远端的合成画像，不要改变实际购物数据的授权。

字段 TTL 与本机代码保持同一量级：温度 30 秒、CPU/内存 3 秒；远端心跳与网络链路也分别检查。这些值用于模拟放置策略，不意味着已实现跨设备心跳或目标设备实时准入。

本阶段的计算时延是声明或注入的估计，不是设备实测。`text_encode` 的短输入未必适合跨设备卸载。目标设备到达时再检查、排队后再次检查、拒绝后的本机可行性、超时执行状态不明等协议规则仍是设计要求，不能从当前 Shadow 代码推导出已实现。

## 验证

- `npm run placement:test`：对真实策略代码进行宿主机运行检查，覆盖影子模式不派发、隐私硬约束、字段过期、传输与冷启动成本、链路过期、本机直通及无本机基线时不派发。
- `PlacementPolicy.test.ets` 已登记到 HarmonyOS Hypium 测试套件；需要 DevEco 工具链运行。
- `git diff --check` 用于提交前格式检查。

当前机器没有文档中曾使用的 `E:/DevEco/DevEco Studio` 工具链，故不能声称 HAP/HAR 构建或 Hypium 真机测试通过。手机适配侧可使用 `./scripts/native-check.ps1 -StudioHome '<实际路径>' -Task all` 补验，并将设备、SDK、报告与日志一起回传。

真实远端执行之前，需要共同冻结：任务和设备画像版本、应用显式授权、目标预装模型摘要、输入输出序列化、目标重新准入、`epoch/attemptId` 去重、取消确认、迟到结果丢弃，以及源端剩余 deadline 传递。目标拒绝后仍要检查本机可行性；断联不等于目标已停止。
