# 鸿蒙作品最小闭环与双机验收汇总

验收日期：2026-09-29（Asia/Shanghai）  
协作分支：`codex/cixin-multi-device-runtime`  
结论口径：只验收作品演示必需的“手机购物结果”和“真实双手机派发”两条链路；它们目前是**两个独立闭环**。正式购物任务由 B 手机执行后回填到 A 的统一闭环尚未实现，不能宣称完整生产多设备购物派发通过。

## 3. 已发现的最小闭环风险

1. **P0：正式购物派发未接入 B。**本次多设备证据是真机计算，但不是商品图片处理；在接入 `image.crop.v1`、真实图片结果校验和购物运行 ID 对应前，不能标记生产双机购物通过。
2. **P1：图片链路存在间歇性失败。**此前同一已知商品图出现过前置 `POLICY_REJECTED / REMOTE_UNAVAILABLE`，合成图出现过 `DEPENDENCIES_NOT_READY:embedding` 与 `RUNTIME_EXECUTION_FAILED`。当前健康探针全绿，但仍需对同图多次运行才可评估稳定性。
3. **P1：新部署异常路径未全面重跑。**取消、物理停止确认和撤销已有旧版真机证据，当前修订的单设备在途租约保护有本地回归；线上新版本只复验成功派发和未授权拒绝。没有把旧证据冒充新版本全量回归。
4. **P2：性能与恢复条件不足。**没有同条件多轮端到端样本；Wi-Fi 真断网、进程被系统杀死、模型质量抽样及设备硬件证明均未纳入本次最小验收，不作相应性能、安全或可用性承诺。

## 4. 作品演示建议与验收门槛

当前可演示：A 的文字或已知目录图片购物结果和电脑调度盘同次运行记录；然后在独立“双机派发验收”页演示 A 配对 B、派发合成任务、B 回执、A 查询完成。演示前确认两机联网、Zeabur Running、B 正在轮询；不要把两个页面的任务描述为同一购物运行。

若作品说明需要声称“购物图片的一段计算真实派给 B”，最小后续门槛只有三项：B 实现 `image.crop.v1` 并对真实测试图回传可验证摘要；云端把该 B 设备纳入受控购物调度且保留合法云端回退；同一个购物 runId 在 A、服务端和 B 均有对应证据并在 A 展示最终商品。完成前总体结论保持**部分通过**。
