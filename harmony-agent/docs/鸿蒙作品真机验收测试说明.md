## 2. 模型和商品目录前置检查

2026-09-29 10:39 左右读取线上 `GET /api/v1/health/capabilities`：HTTP 200，`modelMode=required`，`chat`、`vision`、`embedding`、数据库和 COS 探针均 `available=true`。源码中的模型探针会向所配置的 HTTPS 模型端点发送最小聊天/图片/向量请求，并检查返回文本及向量维度；因此这比仅检查环境变量存在更强，但仍不能证明某次购物运行选用了特定模型。

运行时工具元数据声明：`answer.generate` 使用 `deepseek-flash`，`image.quality_check` 使用 `doubao-seed-2-1-pro-260915`，`text.embedding` 与 `image.embedding` 使用 `doubao-embedding-vision-251215`。商品库统计显示向量 provider 为 `volcengine_doubao_vision`、维度 1024；这些是**配置/工具声明**，不是逐次运行的模型调用日志。

同一次线上能力检查中 `shopping.text=true`、`shopping.read=true`，而 `shopping.image=false`、`shopping.image_upload=false`，原因 `DEPENDENCIES_NOT_READY:catalog`。1975 件商品中，multimodal 向量覆盖 1975 件，visual 向量仅覆盖 1957 件，缺 18 件；catalog 检查返回 `INDEX_COVERAGE_INCOMPLETE`。因此**模型已配置并通过最小探针，图片购物业务仍不具备验收前置条件**。现有 `POST /api/v1/product-pool/embeddings/rebuild` 在生成前会删除选中范围的现有向量；本轮未在生产库调用它。

## 5. 复测步骤与收尾标准

1. 保持只用 `.codextest` 包。确认 HDC 设备、手机 DNS/HTTPS、Zeabur Running 及部署标题，检查 `hdc fport ls` 的 `tcp:8766 tcp:8765 [Reverse]`；监控快照须在数秒内推进。手机“我的”页云端地址应为 `https://cixin.zeabur.app`。任何测试开始前记录源码 SHA、HAP SHA、部署版本、手机网络、SOC/充电、策略与反馈状态。
2. 先读 `/api/v1/health/capabilities` 和 `/api/v1/product-pool/stats`。文字能力可用才做少量受控文字样本；图片能力必须变为 true 后再用团队提供的非私人测试图片。若需修复缺失向量，应设计**只补缺失且不删除现有索引**的任务，先备份并在测试环境验证，再在生产执行；不能把全量 rebuild 当成安全的 18 条修补。
3. 每条真机请求记录用例、输入类别、开关、手机 taskId、云端 runId、服务端终态与模型阶段、候选数、可见质量问题、客户端与云端耗时。取消用例在服务端确认停止前只能标注“客户端取消”；失败样本必须保留在分母中。
4. 补齐 F05、F07、F09、F12–F14 与设备 Worker 校准后，再做至少多轮普通/高质量对照和质量抽样，计算分布统计。未经用户同意不启用反馈；不因手机开关标签推断高质量模型实际调用。

本轮本机原始证据存于 Git 忽略目录 `artifacts/phone-live/20260929-architecture-retest/`，包含 `model-f02-success.private.jpeg`、`model-f02-live-now.private.json`、`model-f07-end.private.json`、`model-f04-end.private.json`、`model-f08-read.private.json`、`model-f10-retry.private.json`、`model-f11-after.private.json`。这些文件可能含搜索原文和屏幕内容，分享前须脱敏。共享文档仅记录最小必要信息。
