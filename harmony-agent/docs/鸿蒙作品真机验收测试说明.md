## 2. 模型和商品目录前置检查

2026-09-29 10:39 左右读取线上 `GET /api/v1/health/capabilities`：HTTP 200，`modelMode=required`，`chat`、`vision`、`embedding`、数据库和 COS 探针均 `available=true`。源码中的模型探针会向所配置的 HTTPS 模型端点发送最小聊天/图片/向量请求，并检查返回文本及向量维度；因此这比仅检查环境变量存在更强，但仍不能证明某次购物运行选用了特定模型。

运行时工具元数据声明：`answer.generate` 使用 `deepseek-flash`，`image.quality_check` 使用 `doubao-seed-2-1-pro-260915`，`text.embedding` 与 `image.embedding` 使用 `doubao-embedding-vision-251215`。商品库统计显示向量 provider 为 `volcengine_doubao_vision`、维度 1024；这些是**配置/工具声明**，不是逐次运行的模型调用日志。

同一次线上能力检查中 `shopping.text=true`、`shopping.read=true`，而 `shopping.image=false`、`shopping.image_upload=false`，原因 `DEPENDENCIES_NOT_READY:catalog`。1975 件商品中，multimodal 向量覆盖 1975 件，visual 向量仅覆盖 1957 件，缺 18 件；catalog 检查返回 `INDEX_COVERAGE_INCOMPLETE`。因此**模型已配置并通过最小探针，图片购物业务仍不具备验收前置条件**。现有 `POST /api/v1/product-pool/embeddings/rebuild` 在生成前会删除选中范围的现有向量；本轮未在生产库调用它。
