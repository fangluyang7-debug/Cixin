# 模块职责边界（V0）

## 1. 文档目的

本文档用于把当前已经确定的功能模块，进一步收束为清晰的职责边界定义。

这里回答的问题不是“怎么实现”，而是：

- 每个模块存在的意义是什么
- 每个模块应该负责什么
- 每个模块明确不负责什么
- 每个模块依赖哪些上游能力
- 每个模块的结果会流向哪里

本文档是后续输入输出设计、技术方案、任务拆分和实现分工的前置约束。

## 2. 使用原则

在阅读和后续扩展本文件时，应遵守以下原则：

1. 一个模块只对自己核心职责负责，不吞并相邻模块职责
2. 模块之间通过明确结果协作，不依赖隐式猜测
3. 增强能力不能篡改主链路的核心判断权
4. 用户当前明确输入优先于系统历史记忆
5. 首版可以裁功能，但不应破坏边界设计

## 3. 一级功能模块职责边界

### 3.1 用户输入与会话启动模块

**定位**

负责把一次用户查询正式启动起来，是整条主链路的入口模块。

**负责**

- 接收用户拍照或上传的图片输入
- 触发一轮新的查询开始
- 建立当前查询会话
- 为本轮后续识别、筛选和展示提供统一会话归属

**不负责**

- 不负责商品识别
- 不负责商品搜索
- 不负责对候选结果做任何判断
- 不负责长期用户记忆的维护

**依赖**

- 用户的图片输入行为
- 会话与状态保持模块

**输出去向**

- 向商品理解模块提供原始输入内容
- 向会话与状态保持模块提供新的查询会话

**边界说明**

它只回答“这次查询从哪里开始”，不回答“用户想买什么”和“应该展示什么”。

### 3.2 商品理解模块

**定位**

负责把图片和用户修正信息转化为可用于检索的商品画像。

**负责**

- 理解输入图片对应的鞋类商品
- 形成结构化商品画像
- 接收用户对关键属性的修正
- 结合用户记忆信息辅助识别纠错

**不负责**

- 不负责跨平台搜索
- 不负责结果排序
- 不负责主动推荐结论
- 不负责展示逻辑

**依赖**

- 用户输入与会话启动模块提供的原始输入内容
- 用户记忆与偏好模块提供的辅助上下文
- 会话与状态保持模块保存的当前会话状态

**输出去向**

- 向跨平台检索与聚合模块提供商品画像
- 向会话与状态保持模块回写识别结果

**边界说明**

它负责把“看到的商品”理解清楚，但不负责决定“哪个候选更值得买”。

### 3.3 跨平台检索与聚合模块

**定位**

负责基于商品画像找回外部候选结果，是“找货”模块。

**负责**

- 根据商品画像发起跨平台检索
- 从多个数据源获取候选商品
- 汇总不同平台的价格、货源和基础来源信息
- 在需要时响应收敛模块的补充检索要求

**不负责**

- 不负责统一候选结果格式
- 不负责解释推荐理由
- 不负责历史价格分析
- 不负责送达时效估算

**依赖**

- 商品理解模块提供的商品画像
- 结果筛选与收敛模块可能补充的筛选约束
- 外部商品数据源

**输出去向**

- 向结果标准化与候选池模块提供原始候选结果

**边界说明**

它负责尽可能找回候选，但不负责把候选变成最终可比较结果。

### 3.4 结果标准化与候选池模块

**定位**

负责把不同来源的候选商品统一成稳定的内部候选池。

**负责**

- 清洗和统一来自不同平台的原始结果
- 保留候选商品的来源关系
- 建立当前会话下的标准化候选池
- 为后续筛选、历史价格、决策辅助和展示提供一致输入

**不负责**

- 不负责理解用户自然语言
- 不负责推荐解释
- 不负责商品详情展示
- 不负责用户偏好记忆

**依赖**

- 跨平台检索与聚合模块提供的原始候选结果
- 会话与状态保持模块维护的当前会话

**输出去向**

- 向结果筛选与收敛模块提供标准化候选池
- 向智能建议模块提供候选集合
- 向历史价格模块提供候选商品
- 向决策辅助模块提供可比较基础结果
- 向会话与状态保持模块保存候选池状态

**边界说明**

它负责“统一结果”，不负责“做出推荐”。

### 3.5 结果筛选与收敛模块

**定位**

负责把用户的后续要求转化为会话内的收敛动作，是多轮交互的核心控制模块。

**负责**

- 接收用户自然语言追加要求
- 把要求转成当前会话的筛选条件
- 基于当前候选池执行过滤、重排或补充检索判断
- 保持多轮收敛过程在同一上下文中持续推进

**不负责**

- 不负责第一轮商品识别
- 不负责外部候选结果标准化
- 不负责最终推荐解释
- 不负责长期用户资料管理

**依赖**

- 当前查询会话
- 商品画像
- 标准化候选池
- 用户记忆与偏好模块提供的辅助上下文

**输出去向**

- 向跨平台检索与聚合模块发出补充检索需求
- 向智能建议模块提供收敛后的候选结果
- 向决策辅助模块提供当前筛选条件和更新后的候选结果
- 向会话与状态保持模块回写当前筛选条件

**边界说明**

它负责让结果变得更贴近用户，但不替代检索模块去“找货”，也不替代建议模块去“说服用户”。

### 3.6 智能建议模块

**定位**

负责在交互过程中主动推进用户决策，是核心用户感知模块之一。

**负责**

- 生成建议卡片
- 输出主动推荐结论
- 基于当前候选结果提示下一步可收敛方向
- 减少用户自己思考和手动筛选的成本

**不负责**

- 不负责直接拉取外部商品数据
- 不负责保存历史价格
- 不负责最终汇总所有比较维度
- 不负责商品详情承载

**依赖**

- 标准化候选池
- 结果筛选与收敛模块产出的当前结果
- 用户记忆与偏好模块提供的长期上下文

**输出去向**

- 向决策辅助模块提供建议理由和主动推荐结论
- 向前台结果展示提供建议卡片

**边界说明**

它负责“主动引导”，但不拥有最终候选事实来源。

### 3.7 历史价格模块

**定位**

负责提供时间维度下的价格参考，是独立决策输入模块。

**负责**

- 获取或组织候选商品的历史价格信息
- 生成当前价格位置的参考判断
- 将历史价格带入列表级比较
- 在商品详情中提供更完整的价格时间参考

**不负责**

- 不负责候选结果搜索
- 不负责主动推荐结论生成
- 不负责用户偏好维护
- 不负责配送时效估算

**依赖**

- 结果标准化与候选池模块提供的候选商品
- 缓存、降级与恢复模块可能提供的价格缓存

**输出去向**

- 向决策辅助模块提供历史价格参考信息
- 向前台列表展示提供列表级价格比较信息
- 向商品详情模块提供详情级历史价格信息

**边界说明**

它负责补上“现在买划不划算”这一维，但不单独决定推荐顺序。

### 3.8 决策辅助模块

**定位**

负责汇总多种比较维度，形成最终可读的判断信息。

**负责**

- 汇总价格、货源、平台、历史价格、时效等决策信息
- 形成“为什么值得优先看”的综合解释
- 为列表展示和详情判断提供统一比较结果

**不负责**

- 不负责原始候选商品拉取
- 不负责自然语言解析
- 不负责长期用户记忆维护
- 不负责发起新的补充检索

**依赖**

- 标准化候选池
- 智能建议模块
- 历史价格模块
- 配送时效与地理位置模块
- 结果筛选与收敛模块的当前约束

**输出去向**

- 向前台结果展示提供综合比较信息
- 向商品详情模块提供更完整的决策解释

**边界说明**

它负责“把信息组织成判断依据”，但不负责替用户完成最终购买动作。

### 3.9 商品详情模块

**定位**

负责承接用户从列表进入单个商品的深看动作，是主链路末端的重要落点。

**负责**

- 展示单个候选商品的完整信息
- 承接用户对某个候选商品的进一步判断
- 组织商品级推荐理由、历史价格和基础购买信息
- 为后续跳转购买提供决策落点

**不负责**

- 不负责拉起新的商品识别流程
- 不负责跨平台检索
- 不负责多轮筛选条件的解析
- 不负责长期用户记忆维护

**依赖**

- 前台列表展示中的候选选择
- 决策辅助模块提供的综合判断信息
- 历史价格模块提供的详情级历史价格信息

**输出去向**

- 向用户提供单商品决策视图
- 向会话与状态保持模块回写当前浏览状态

**边界说明**

它负责“看清一个候选”，不负责“重新决定所有候选”。

### 3.10 用户记忆与偏好模块

**定位**

负责维护用户长期稳定信息和偏好，是横向增强模块。

**负责**

- 记录用户基础资料，例如身高、体重、常用尺码
- 记录用户长期偏好，例如预算区间、品牌偏好、平台偏好、店铺偏好
- 允许用户主动编辑和确认系统记住的信息
- 为识别纠错、筛选收敛、建议生成提供上下文支持

**不负责**

- 不负责替代用户当前明确输入
- 不负责独立生成候选商品
- 不负责单独做出购买推荐
- 不负责决定会话是否结束

**依赖**

- 用户主动提供或确认的资料与偏好
- 会话过程中积累的可保留偏好信息

**输出去向**

- 向商品理解模块提供识别纠错辅助
- 向结果筛选与收敛模块提供默认偏好上下文
- 向智能建议模块提供个性化参考

**边界说明**

它负责让系统“记得住用户”，但不允许压过用户当前这次明确表达的要求。

### 3.11 配送时效与地理位置模块

**定位**

负责提供价格之外的附加时效参考。

**负责**

- 获取或读取用户地理位置
- 结合商家发货地和发货信息估算预计送达时间
- 把时效信息作为附加参考送入比较过程

**不负责**

- 不负责核心候选商品排序
- 不负责主动推荐结论
- 不负责伪造不存在的物流信息
- 不负责长期用户偏好管理

**依赖**

- 用户位置
- 候选商品及商家相关信息

**输出去向**

- 向决策辅助模块提供预计送达时间参考
- 向商品详情模块提供附加时效说明

**边界说明**

它只提供附加参考，不应在信息不可靠时给出过强结论。

## 4. 支撑性模块职责边界

### 4.1 会话与状态保持模块

**定位**

负责维持整个多轮查询过程的状态连续性。

**负责**

- 保存查询会话
- 维护识别结果、筛选条件、候选池和当前展示状态的一致性
- 保证多轮交互时上下文不丢失

**不负责**

- 不负责识别商品
- 不负责生成候选商品
- 不负责生成推荐理由

**依赖**

- 各业务模块回写的当前状态

**输出去向**

- 为商品理解、结果筛选与收敛、前台展示等模块提供会话上下文

**边界说明**

它负责“把状态接住”，不负责“创造业务结果”。

### 4.2 缓存、降级与恢复模块

**定位**

负责保障外部能力波动时主链路尽量不断。

**负责**

- 缓存中间结果和可复用结果
- 在外部接口不稳定时提供降级结果
- 为演示和基础可用性提供恢复能力

**不负责**

- 不负责定义业务结果逻辑
- 不负责替代正式数据源长期存在
- 不负责修改用户偏好和会话语义

**依赖**

- 各业务模块产出的中间结果
- 外部能力的可用性状态

**输出去向**

- 向跨平台检索与聚合模块提供降级候选结果
- 向历史价格模块提供缓存价格数据
- 向会话与状态保持模块提供恢复所需结果

**边界说明**

它负责“让系统别断”，不负责“决定系统应该推荐什么”。

## 5. 当前文档结论

截至当前版本，模块边界已经收束出几个关键判断：

- 主链路核心模块是：用户输入与会话启动、商品理解、跨平台检索与聚合、结果标准化与候选池、结果筛选与收敛、智能建议、决策辅助、商品详情
- 横向增强模块是：用户记忆与偏好、配送时效与地理位置
- 独立决策输入模块是：历史价格
- 系统稳定性支撑模块是：会话与状态保持、缓存、降级与恢复
