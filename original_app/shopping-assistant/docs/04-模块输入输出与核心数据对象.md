# 模块输入输出与核心数据对象（V0）

## 1. 文档目的

本文档用于在模块职责已经明确的前提下，进一步定义：

- 当前系统需要哪些核心数据对象
- 每类对象至少应承载什么信息
- 每个模块主要输入什么对象
- 每个模块主要输出什么对象
- 主链路和增强链路中的对象如何流转

这里讨论的是“数据契约层”，不是接口字段最终命名，也不是数据库落表方案。

## 2. 使用原则

为了避免后续接口、数据库、缓存和前端状态设计各自发散，当前数据对象设计遵循以下原则：

1. 先定义对象职责，再定义技术实现
2. 一个对象可以被多个模块消费，但应有清晰的主要来源
3. 会话级数据和用户级数据分开
4. 主链路对象和增强对象分开
5. 用户当前输入优先于历史记忆
6. 当前文档描述“至少应包含的信息”，不强行提前确定最终字段名

## 3. 核心数据对象总览

当前建议把核心数据对象分为 5 组。

### 3.1 用户级对象

- 用户基础资料
- 用户长期偏好
- 用户记忆确认结果

### 3.2 会话级对象

- 查询会话
- 原始输入内容
- 用户自然语言请求
- 当前筛选条件

### 3.3 目标商品与检索对象

- 商品画像
- 检索请求
- 原始候选结果

### 3.4 候选结果对象

- 标准化候选商品
- 标准化候选池

### 3.5 决策增强对象

- 智能建议结果
- 历史价格参考
- 预计送达时间参考
- 决策辅助信息
- 商品详情视图数据

## 4. 核心数据对象定义

### 4.1 用户基础资料

**作用**

表示用户相对稳定的基础信息，用于帮助识别纠错和结果贴合。

**作用域**

用户级对象。

**至少应包含**

- 身高
- 体重
- 常用尺码
- 可能影响鞋类判断的基础习惯信息

**主要来源**

- 用户主动填写
- 用户后续编辑确认

**主要去向**

- 商品理解模块
- 用户记忆与偏好模块

### 4.2 用户长期偏好

**作用**

表示用户持续性的购物倾向，用于减少重复输入。

**作用域**

用户级对象。

**至少应包含**

- 预算范围
- 品牌偏好
- 平台偏好
- 店铺偏好
- 风格或场景偏好

**主要来源**

- 用户主动设置
- 历史查询过程中的可保留偏好

**主要去向**

- 结果筛选与收敛模块
- 智能建议模块
- 用户记忆与偏好模块

### 4.3 用户记忆确认结果

**作用**

表示用户对系统记忆内容是否确认、修改或拒绝，用于防止系统长期保留错误记忆。

**作用域**

用户级对象。

**至少应包含**

- 被确认的记忆项
- 被修改的记忆项
- 被拒绝保留的记忆项
- 最近一次确认时间

**主要来源**

- 用户记忆编辑与确认行为

**主要去向**

- 用户记忆与偏好模块

### 4.4 查询会话

**作用**

表示围绕一次拍照或上传开始的完整查询过程，是所有会话级对象的归属锚点。

**作用域**

会话级对象。

**至少应包含**

- 会话标识
- 会话开始时间
- 当前所处阶段
- 当前关联的商品画像
- 当前关联的候选池
- 当前筛选条件
- 当前浏览状态

**主要来源**

- 用户输入与会话启动模块

**主要去向**

- 会话与状态保持模块
- 商品理解模块
- 结果筛选与收敛模块

### 4.5 原始输入内容

**作用**

表示一次查询开始时用户提供的素材与原始输入。

**作用域**

会话级对象。

**至少应包含**

- 图片内容或图片引用
- 上传方式或拍摄方式
- 输入时间
- 与当前会话的关联关系

**主要来源**

- 用户输入与会话启动模块

**主要去向**

- 商品理解模块
- 会话与状态保持模块

### 4.6 用户自然语言请求

**作用**

表示用户在查询过程中追加的原始自然语言表达。

**作用域**

会话级对象。

**至少应包含**

- 用户原始文本
- 所属会话
- 输入时间
- 是第几轮追加要求

**主要来源**

- 用户在收敛阶段的自然语言输入

**主要去向**

- 结果筛选与收敛模块
- 会话与状态保持模块

### 4.7 当前筛选条件

**作用**

表示系统已经理解并生效的筛选约束，是自然语言请求的结构化结果。

**作用域**

会话级对象。

**至少应包含**

- 价格约束
- 时间约束，例如需要在几天内收到货、是否有及时性要求
- 店铺约束
- 是否有货约束
- 风格或颜色约束
- 平台或品牌约束
- 当前排序或优先考虑规则

**主要来源**

- 结果筛选与收敛模块

**主要去向**

- 跨平台检索与聚合模块
- 智能建议模块
- 决策辅助模块
- 会话与状态保持模块

### 4.8 商品画像

**作用**

表示系统对目标鞋类商品的结构化理解，是检索的基础对象。

**作用域**

会话级对象。

**至少应包含**

- 鞋类类别
- 品牌
- 尺码
- 颜色
- 款式特征
- 用户修正后的关键属性
- 用于检索的核心关键词

**主要来源**

- 商品理解模块

**主要去向**

- 跨平台检索与聚合模块
- 结果筛选与收敛模块
- 会话与状态保持模块

### 4.9 检索请求

**作用**

表示系统准备发往外部检索侧的查询描述，是商品画像与筛选条件的合成物。

**作用域**

会话级对象。

**至少应包含**

- 商品目标描述
- 核心检索关键词
- 当前筛选条件
- 平台范围或检索范围

**主要来源**

- 跨平台检索与聚合模块

**主要去向**

- 外部商品数据源

### 4.10 原始候选结果

**作用**

表示来自不同平台、尚未统一格式的原始候选商品返回结果。

**作用域**

会话级对象。

**至少应包含**

- 平台原始商品信息
- 平台价格信息
- 店铺或货源信息
- 商品链接或来源引用
- 平台侧附带的其他可比较信息

**主要来源**

- 跨平台检索与聚合模块

**主要去向**

- 结果标准化与候选池模块
- 缓存、降级与恢复模块

### 4.11 标准化候选商品

**作用**

表示单个候选商品的统一内部表示，是候选池的基本单位。

**作用域**

候选级对象。

**至少应包含**

- 候选商品标识
- 商品标题
- 平台信息
- 当前价格
- 店铺类型
- 货源状态
- 商品图片
- 商品链接
- 与商品画像的匹配关系

**主要来源**

- 结果标准化与候选池模块

**主要去向**

- 标准化候选池
- 历史价格模块
- 决策辅助模块
- 商品详情模块

### 4.12 标准化候选池

**作用**

表示当前会话中的统一候选商品集合，是后续收敛、建议和比较的中心对象。

**作用域**

会话级对象。

**至少应包含**

- 候选商品列表
- 当前候选总量
- 已应用的筛选条件
- 当前候选排序状态
- 与当前会话的关联关系

**主要来源**

- 结果标准化与候选池模块

**主要去向**

- 结果筛选与收敛模块
- 智能建议模块
- 历史价格模块
- 决策辅助模块
- 会话与状态保持模块

### 4.13 智能建议结果

**作用**

表示系统针对当前候选结果给出的主动引导输出。

**作用域**

会话级对象。

**至少应包含**

- 建议卡片列表
- 主动推荐结论
- 每条建议背后的触发依据
- 下一步可继续收敛的方向

**主要来源**

- 智能建议模块

**主要去向**

- 决策辅助模块
- 前台结果展示

### 4.14 历史价格参考

**作用**

表示某个候选商品在时间维度上的价格判断结果。

**作用域**

候选级对象。

**至少应包含**

- 历史价格序列或其引用
- 历史最低价
- 当前价格所处位置
- 是否值得当前购买的参考结论

**主要来源**

- 历史价格模块

**主要去向**

- 决策辅助模块
- 前台列表展示
- 商品详情模块

### 4.15 预计送达时间参考

**作用**

表示与候选商品相关的预计送达时效信息。

**作用域**

候选级对象。

**至少应包含**

- 用户位置参考
- 商家发货地或发货时效信息
- 估算送达时间
- 时效可靠性说明

**主要来源**

- 配送时效与地理位置模块

**主要去向**

- 决策辅助模块
- 商品详情模块

### 4.16 决策辅助信息

**作用**

表示系统已经组织好的综合比较信息，是列表展示和详情解释的核心对象。

**作用域**

候选级对象和会话级对象的混合输出。

**至少应包含**

- 价格比较结果
- 货源比较结果
- 历史价格参考
- 主动推荐理由
- 时效附加参考
- 当前推荐优先级依据

**主要来源**

- 决策辅助模块

**主要去向**

- 前台结果展示
- 商品详情模块

### 4.17 商品详情视图数据

**作用**

表示用户点进单个候选商品后，需要一次性看到的完整决策数据集合。

**作用域**

候选级对象。

**至少应包含**

- 候选商品基础信息
- 推荐理由
- 历史价格参考
- 时效附加参考
- 购买跳转所需基础信息

**主要来源**

- 商品详情模块

**主要去向**

- 前台商品详情页

## 6. 主链路对象流转

当前主链路最小对象流转建议如下：

`用户拍照/上传`
-> `原始输入内容`
-> `查询会话`
-> `商品画像`
-> `检索请求`
-> `原始候选结果`
-> `标准化候选池`
-> `智能建议结果`
-> `历史价格参考`
-> `决策辅助信息`
-> `商品详情视图数据 / 列表展示结果`

这条链路对应的是“从输入到可比较结果”的最小闭环。

## 7. 多轮收敛对象流转

当用户继续追加要求时，建议按以下对象流转推进：

`用户自然语言请求`
-> `当前筛选条件`
-> 作用于 `查询会话 + 商品画像 + 标准化候选池`
-> 形成 `更新后的候选结果集合`
-> 重新生成 `智能建议结果`
-> 重新生成 `决策辅助信息`
-> 刷新 `列表展示结果 / 商品详情视图数据`

如果当前候选池不足以支撑要求，再由：

`当前筛选条件`
-> `检索请求`
-> `补充检索`

## 8. 横向增强对象流转

### 8.1 用户记忆增强流

`用户基础资料 + 用户长期偏好 + 用户记忆确认结果`
-> `商品理解模块`
-> `结果筛选与收敛模块`
-> `智能建议模块`

### 8.2 历史价格增强流

`标准化候选商品`
-> `历史价格参考`
-> `决策辅助信息`
-> `列表展示 / 商品详情`

### 8.3 配送时效增强流

`用户位置 + 商家发货信息 + 标准化候选商品`
-> `预计送达时间参考`
-> `决策辅助信息`
-> `商品详情`

## 9. 当前文档结论

到这一层为止，当前系统已经形成了三类稳定约束：

1. 模块边界已经由 `03` 固定
2. 核心数据对象已经在本文件中固定
3. 模块与对象之间的主要输入输出关系已经固定
