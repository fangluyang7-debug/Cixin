# 前端联调接口契约

本文档是前端接入后端的当前权威接口说明。前端只需要按这里的主链路调用；商品池导入、embedding 重建、ANN 诊断等维护接口不应出现在普通用户 App 流程里。

## 1. 当前联调基线

- 云端 API：`https://apiserver.zeabur.app`
- 本地 API：`http://localhost:3000`
- 当前主路线：`用户上传图 -> 豆包识图 -> 云端 bbox 裁剪 -> 豆包图片 embedding -> 商品池标签召回 + ANN 召回 -> 候选结果`
- 用户上传图所有实时处理都在云端完成。
- 本地 GPU Worker 只用于离线商品图处理，不是前端依赖。
- 坐标统一使用 `0-1` normalized bbox。

2026-06-01 云端 smoke 已通过：

```json
{
  "health": "ok",
  "totalProducts": 30,
  "searchableProducts": 30,
  "embeddingCount": 30,
  "candidateCount": 27,
  "queryEmbeddingProvider": "volcengine_doubao_vision",
  "queryEmbeddingModel": "doubao-embedding-vision-251215",
  "queryEmbeddingDimension": 1024
}
```

## 2. 通用响应结构

成功：

```json
{
  "success": true,
  "requestId": "req_xxx",
  "data": {},
  "error": null
}
```

失败：

```json
{
  "success": false,
  "requestId": "req_xxx",
  "data": null,
  "error": {
    "code": "ERROR_CODE",
    "message": "ERROR_CODE",
    "details": {}
  }
}
```

前端判断接口是否成功时，应优先看：

1. HTTP 状态码是否为 `2xx`
2. `success === true`
3. `error === null`

## 3. 前端主调用顺序

推荐主链路：

```text
POST /api/v1/assets/images
-> POST /api/v1/sessions
-> GET /api/v1/sessions/:sessionId/search-events
-> GET /api/v1/sessions/:sessionId/candidates
-> POST /api/v1/sessions/:sessionId/candidates/more       可选，用户点击查看更多
-> POST /api/v1/sessions/:sessionId/subject-selection   可选，用户调整框选后调用
-> POST /api/v1/sessions/:sessionId/turns               可选，多轮自然语言筛选
```

页面恢复或 App 重新进入时：

```text
GET /api/v1/sessions/:sessionId
-> GET /api/v1/sessions/:sessionId/candidates
```

## 5. 上传图片

`POST /api/v1/assets/images`

用户真实上传必须使用 `multipart/form-data`，字段名为 `file`。

### 5.1 请求字段

```text
file=<image file>
variantType=compressed_recognition
sourceType=camera | album | demo
isPrimaryRecognitionAsset=true
```

可选字段：

```text
assetGroupId=<asset_group_xxx>
clientContext=<json string>
```

`variantType` 可选值：

- `compressed_recognition`：前端压缩后的主识别图，主流程使用这个。
- `original_source`：原图，按需补传。
- `demo_asset`：演示/维护资源，不作为用户主上传图。

### 5.2 返回字段

```json
{
  "assetId": "asset_xxx",
  "assetGroupId": "asset_group_xxx",
  "variantType": "compressed_recognition",
  "isPrimaryRecognitionAsset": true,
  "uploadStatus": "uploaded",
  "imageRef": {
    "assetId": "asset_xxx",
    "provider": "tencent_cos",
    "bucketGroup": "compressed-recognition",
    "bucketName": "hacson-recognition-dev-1436975351",
    "region": "ap-guangzhou",
    "objectKey": "2026/06/01/...",
    "publicUrl": "https://..."
  },
  "fileMeta": {
    "originalName": "shoe.jpg",
    "contentType": "image/jpeg",
    "size": 123456
  }
}
```

前端只需要保存 `assetId`。`assetGroupId` 用于同一组图片关联，当前主链路不是必填。

## 6. 创建搜索会话

`POST /api/v1/sessions`

### 6.1 请求

```json
{
  "assetId": "asset_xxx",
  "entrySource": "android_app",
  "categoryHint": "shoe"
}
```

如用户已登录，可带：

```text
Authorization: Bearer <jwt>
```

带 JWT 创建的 session 会绑定用户，并把用户画像中的相关偏好带入初始筛选。未登录仍可完整体验匿名搜索流程。

### 6.2 返回核心结构

```json
{
  "session": {
    "sessionId": "sess_xxx",
    "status": "ready",
    "stage": "candidate_ready",
    "currentTurnIndex": 0,
    "entrySource": "android_app",
    "userId": null,
    "startedAt": "2026-06-01T08:00:00.000Z",
    "lastActiveAt": "2026-06-01T08:00:00.000Z",
    "degraded": false
  },
  "productProfile": {},
  "queryImagePreprocess": {},
  "activeFilter": {},
  "candidateSummary": {
    "candidateSnapshotId": "cand_snap_xxx",
    "candidateCount": 27
  }
}
```

`status` 常见值：

- `ready`：结果已生成。
- `degraded_ready`：结果可展示，但存在降级原因。

`stage` 常见值：

- `candidate_ready`：候选已生成。
- `subject_selection_required`：自动框选不可靠，需要用户手动框选后再搜。

`productProfile` 是后端识图模型输出并持久化后的标签。前端可直接用于调试展示，但不需要再回传给后端做搜索。

```json
  "brand": "Puma",
  "modelLine": null,
  "colorFamily": "black_white",
  "colorway": "Dark Brown Off White",
  "shoeType": "lifestyle",
  "size": null,

  "styleTags": [
    "low_top",
    "leather_upper",
    "lace_up"
  ],
  "sceneTags": [
    "casual",
    "commute"
  ],
  "keywords": [
    "Puma sneakers",

  ],
  "confidence": 0.9,
  "raw": {
    "provider": "openai_compatible_vision",
```

- `raw.subjectDetection`：识图模型给出的主体框信息，前端主要使用 `queryImagePreprocess` 中已经标准化后的结果。

## 8. 用户图预处理 queryImagePreprocess

`queryImagePreprocess` 表示后端对用户上传图的主体定位、裁剪和 embedding 状态。前端绘制亮框时只使用这里的 `selectedBox`、`detectedBoxes` 和 `imageSize`。

```json
{
  "preprocessSnapshotId": "query_pre_xxx",
  "assetId": "asset_xxx",
  "status": "ready",
  "selectedBox": {
    "x": 0.18,
    "y": 0,
    "width": 0.82,
    "height": 0.94,
    "confidence": 0.96,
    "label": "shoe_pair"
  },
  "detectedBoxes": [
    {
      "x": 0.21,
      "y": 0,
      "width": 0.67,
      "height": 0.92,
      "confidence": 0.96,
      "label": "shoe"
    }
  ],
  "selectionSource": "auto",
  "imageSize": {
    "width": 1280,
    "height": 1707
  },
  "embedding": {
    "provider": "volcengine_doubao_vision",
    "model": "doubao-embedding-vision-251215",
    "dimension": 1024,
    "vectorHash": "sha256..."
  },
  "cropImageRef": {
    "provider": "tencent_cos",
    "bucketGroup": "demo-assets",
    "objectKey": "2026/06/01/embedding-inputs/queries/..."
  }
}
```

`status`：

- `ready`：后端已完成裁剪图、query embedding 和候选搜索。
- `needs_user_selection`：自动框不可靠，前端应让用户手动框选。

`selectionSource`：

- `auto`：系统自动框。
- `user_adjusted`：用户调整后的框。
- `manual`：人工或调试指定。

### 8.1 bbox 坐标规则

坐标全部基于原图尺寸归一化：

```json
{
  "x": 0.18,
  "y": 0.0,
  "width": 0.82,
  "height": 0.94
}
```

换算像素：

```text
left = x * imageWidth
top = y * imageHeight
boxWidth = width * imageWidth
boxHeight = height * imageHeight
```

前端如果用 `BoxFit.contain`、裁剪显示或自适应容器，需要先计算图片在容器内的实际显示区域，再把 normalized bbox 映射到显示区域。

## 9. 用户调整框选范围

`POST /api/v1/sessions/:sessionId/subject-selection`

当用户拖动或缩放亮框后调用。后端会用新的 bbox 重新裁剪、重新生成 query embedding、重新检索，并写入新的候选快照。

### 9.1 请求

```json
{
  "assetId": "asset_xxx",
  "box": {
    "x": 0.08,
    "y": 0.05,
    "width": 0.84,
    "height": 0.82
  },
  "selectionSource": "user_adjusted"
}
```

`assetId` 可省略；省略时使用当前 session 的原始上传图。

### 9.2 返回

返回结构与 `GET /sessions/:sessionId` 基本一致，并额外包含：

```json
{
  "subjectSelection": {
    "preprocessSnapshotId": "query_pre_xxx",
    "candidateSnapshotId": "cand_snap_xxx"
  }
}
```

前端处理规则：

1. 用返回的 `queryImagePreprocess.selectedBox` 覆盖本地框选状态。
2. 用返回的 `candidateSummary.candidateSnapshotId` 或 `subjectSelection.candidateSnapshotId` 判断结果已刷新。
3. 重新调用 `GET /sessions/:sessionId/candidates` 或直接等待 SSE 的 `candidate_batch`。

### 9.3 相关错误

- `SUBJECT_SELECTION_BOX_REQUIRED`：缺少 `box`。
- `INVALID_SUBJECT_SELECTION_BOX`：bbox 越界或尺寸过小。
- `SESSION_NOT_FOUND`：会话不存在。
- `IMAGE_ASSET_NOT_FOUND`：指定图片资源不存在。

合法 bbox 必须满足：

```text
0 <= x <= 1
0 <= y <= 1
0 < width <= 1
0 < height <= 1
x + width <= 1
y + height <= 1
width >= 0.02
height >= 0.02
```

## 10. 搜索进度 SSE

`GET /api/v1/sessions/:sessionId/search-events`

Header：

```text
Accept: text/event-stream
```

当前实现是“事件回放”：session 创建完成后，前端也可以再打开 SSE 拿到完整进度事件。后续改成实时异步任务时，事件类型保持不变。

事件类型：

```text
search_started
profile_ready
subject_detected
subject_selection_updated
recall_completed
embedding_ready
verify_progress
candidate_batch
search_completed
```

## 12. 查看更多候选商品

`POST /api/v1/sessions/:sessionId/candidates/more`

用于用户点击“查看更多”时继续拉取后续全局排序候选。该接口复用当前 session 的商品画像、用户图 embedding、当前筛选条件和最新候选快照，不会重新识图，不会重新生成 query embedding，也不会按平台分配名额。

### 12.1 请求

```json
{
  "cursor": "cand_cursor_xxx",
  "limit": 30
}
```

字段说明：

- `cursor`：可选。推荐传 `GET /candidates` 或上一次 `more` 返回的 `cursor.nextCursor`。
- `limit`：可选，默认 `30`，最大 `100`。

如果前端没有传 `cursor`，后端会尝试使用当前最新候选快照上的有效 cursor。

### 12.2 返回

```json
{
  "candidateSnapshotId": "cand_snap_xxx",
  "cursor": {
    "nextCursor": "cand_cursor_xxx",
    "hasMore": true,
    "offset": 60,
    "limit": 30,
    "returnedRange": {
      "from": 31,
      "to": 60
    },
    "expiresAt": "2026-06-02T12:00:00.000Z"
  },
  "items": []
}
```

`items[]` 的字段与 `GET /api/v1/sessions/:sessionId/candidates` 中的 `CandidateItem` 完全一致。前端应将返回的 `items` 追加到当前列表，不要覆盖已有首屏结果。

### 12.3 前端处理规则

- 默认按后端返回顺序追加展示。
- `rank` 是后端全局排序序号，第 31 条会返回 `rank=31`。
- `pageIndex=0` 代表首屏结果，`pageIndex=1` 代表第一次查看更多结果。
- `hasMore=false` 时隐藏或禁用“查看更多”按钮。
- 多轮筛选或用户调整 bbox 后，旧 cursor 会失效，应重新读取最新 `GET /candidates`。
- 如果返回 `CANDIDATE_CURSOR_EXPIRED`，前端重新调用 `GET /candidates` 获取最新 cursor。

## 14. 多轮自然语言筛选

`POST /api/v1/sessions/:sessionId/turns`

### 14.1 请求

```json
{
  "message": "500以内，只看有货，不要拼多多"
}
```

### 14.2 返回

返回会包含：

- `assistantMessage`
- `effectiveFilter`
- `conversationState`
- `candidates`
- `suggestions`
- `memoryProposals`，登录态下可能出现

前端可以直接用返回的 `candidates` 刷新列表；也可以再调用：

```text
GET /api/v1/sessions/:sessionId/candidates
```

### 14.3 前端规则

- 多轮筛选只影响当前 session。
- 长期用户画像不会被自动写入，必须走用户确认。
- 前端展示以 `effectiveFilter` 和最新候选结果为准，不以 LLM 文案为准。

## 16. 商品池管理接口

以下接口用于后台维护、数据导入、调试和运营，不进入普通 App 用户链路。

需要 `x-maintenance-token`：

- `POST /api/v1/product-pool/import`
- `GET /api/v1/product-pool/batches`
- `GET /api/v1/product-pool/batches/:batchId`
- `POST /api/v1/product-pool/batches/:batchId/retry`
- `POST /api/v1/product-pool/batches/delete`
- `PATCH /api/v1/product-pool/products/:productId`
- `POST /api/v1/product-pool/products/delete`
- `POST /api/v1/product-pool/embeddings/rebuild`
- `POST /api/v1/product-pool/ann/diagnose`

不需要 token：

- `GET /api/v1/product-pool/stats`
- `GET /api/v1/product-pool/products`
- `GET /api/v1/product-pool/products/:productId`

`POST /api/v1/product-pool/import` 是异步接口，立即返回：

```json
{
  "batchId": "product_batch_xxx",
  "status": "queued",
  "mode": "async",
  "pollPath": "/api/v1/product-pool/batches/product_batch_xxx"
}
```

前端 App 不应直接使用这些维护接口。
