# 本地商品池导入与联调清单

本文档用于本地或云端导入真实商品数据后的快速联调。当前商品池主路线已经从早期 fake 样例切换为“清洗后的平台商品 JSON -> ProductPool -> 商品图 embedding -> ANN 检索”。

权威前端接口以 `docs/16-前端联调接口契约.md` 为准；后续能力 TODO 以 `docs/17-后续能力TODO总表.md` 为准。

## 1. 当前基线

云端当前基线：

- API：`https://apiserver.zeabur.app`
- 早期伪造 50 条商品数据已清理。
- 当前线上商品池使用首批八爪鱼清洗后的淘宝/天猫鞋类商品。
- 当前线上商品已生成真实图片 embedding。
- 云端 smoke 已验证上传、识图、用户图裁剪、query embedding、ANN + 标签召回、候选返回和 search-events。

本地数据库默认位置：

```text
services/api-server/prisma/dev.db
```

如果 `.env` 中设置了其他 `DATABASE_URL`，则以 `.env` 为准。

## 2. 本地商品池模式

复制环境变量文件：

```powershell
Copy-Item .env.example .env
```

本地联调商品池时，`.env` 至少确认：

```env
DATABASE_URL=file:./dev.db
SEARCH_PROVIDER=local_product_pool
PRODUCT_DATA_PROVIDER=local_product_pool
OBJECT_STORAGE_PROVIDER=mock
MODEL_PROVIDER=mock
VISION_PROVIDER=mock
CHAT_PROVIDER=mock
API_JSON_BODY_LIMIT=10mb
```

如果要本地验证真实 COS 或真实模型，需要按 `.env.example` 补齐腾讯云 COS、豆包视觉、豆包 embedding、DeepSeek 等变量。不要把 `.env` 提交到 GitHub。

## 4. 导入商品数据

后端兼容两种 JSON：

- 后端原生导入格式：`{ "batchSource": "...", "items": [...] }`
- 采集端格式：`taobao_product_pool.v2`，即 `{ "schemaVersion": "...", "products": [...] }`

导入真实或清洗后的商品文件：

```powershell
node scripts/import-product-pool.mjs --file "artifacts\product-pool\taobao-test-formal-first30-verified.json" --base-url http://localhost:3000 --wait
```

导入云端：

```powershell
node scripts/import-product-pool.mjs `
  --file "artifacts\product-pool\taobao-test-formal-first30-verified.json" `
  --base-url https://apiserver.zeabur.app `
  --env-file .env `
  --wait
```

说明：

- `--wait` 会轮询导入批次，直到完成或失败。
- 云端导入需要 `.env` 中存在 `MAINTENANCE_API_TOKEN`。
- 大批量导入时建议每批 30-50 条，控制在线 embedding 成本。
- `product-pool:import:fake` 仅保留为本地开发脚本，不作为当前云端商品池来源。

## 6. 可视化运维界面

启动 API 和 Web：

```powershell
npm run api:dev
npm run web:dev
```

打开：

```text
http://localhost:5173/product-pool.html
```

页面顶部可配置 API 地址和维护 Token。当前界面支持批次质量报告、失败重试、回滚预检与执行、批次删除、商品编辑与批量删除、verified JSON 导入和 embedding 重建。

回滚限制：

- 只有迁移 `000008_product_import_rollback` 上线后产生变更日志的批次可回滚。
- 正在排队或处理中的批次不可回滚。
- 商品已被后续批次修改时会记录冲突并拒绝覆盖。
- 页面执行回滚前会先调用 dry-run 预检。

详细说明见 `docs/25-商品池可视化运维与批次回滚.md`。

## 9. 导入后的验收标准

导入真实样本后，`GET /api/v1/product-pool/stats` 应满足：

```text
totalProducts > 0
searchableProducts > 0
embeddingCount > 0
```

如果 `totalProducts` 有值但 `searchableProducts` 为 0，通常说明商品标签审核没有通过，需检查 `Product.tagStatus` 和 `ProductTagAudit`。

如果 `searchableProducts` 有值但候选没有 ANN 分数，优先检查：

```text
PRODUCT_DATA_PROVIDER=local_product_pool
EMBEDDING_PROVIDER 是否为真实 provider
商品 embedding 是否已覆盖当前 provider/model/dimension
```

云端完整 smoke：

```powershell
npm run api:smoke:cloud -- `
  -BaseUrl https://apiserver.zeabur.app `
  -ImagePath D:\shopping-assistant\user_image_sample.jpg
```

该 smoke 用于验证上传、识图、用户图裁剪、query embedding、候选返回和 search-events，不负责导入商品或重建商品 embedding。
