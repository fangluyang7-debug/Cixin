# 淘宝天猫商品数据清洗验链与入库说明

## 1. 目标

本流程用于把淘宝/天猫采集器产出的原始商品数据，转换为后端 `ProductPool` 可直接导入的标准商品 JSON，并在入库前验证商品链接和图片链接当前可访问。

核心原则：

- 原始爬虫数据不直接入库。
- 后端只接收清洗、去重、验链后的标准商品 JSON。
- 商品展示和 embedding 不长期依赖淘宝/天猫外部图片链接，入库时必须把图片转存到 COS。
- embedding 向量只存数据库，不需要额外创建对象存储向量桶。

## 2. 完整链路

```text
爬虫完成一次工作流
-> 本地产生 JSONL 或 JSON 数组文件
-> normalize-octoparse-taobao.mjs 清洗、去重、标准化
-> verify-product-links.mjs 验证商品链接和图片链接
-> import-product-pool.mjs 将 verified JSON 提交给后端
-> 后端 ProductImportAdapter 标准化导入数据
-> 后端写入 Product / ProductImportBatch 等数据库表
-> 后端把商品图片转存到腾讯云 COS
-> 后端或离线 worker 对图片做 embedding 预处理
-> 生成图片 embedding
-> embedding 写入数据库 ProductImageEmbedding
-> 商品进入 ANN 可检索池
```

后端入口规则：

- 清洗脚本和验链脚本只负责把外部数据整理成 ProductPool 导入 JSON。
- 后端真正接收数据时，会先经过 `ProductImportAdapter`，再进入 `ProductPoolService`。
- 后续淘宝详情页、天猫详情页、八爪鱼、人工样本或官方 API 的字段差异，都必须先在 adapter 层转换。
- 商品池核心逻辑不得直接解析来源字段。
- `rawPayload` 只用于回溯和审计，不作为核心搜索、排序、同款判断的主要输入。

## 3. 原始输入要求

清洗脚本支持两种输入：

- JSONL：一行一个商品对象，推荐爬虫长期使用。
- JSON 数组：八爪鱼等工具导出的数组文件。

字段可使用中文或英文别名。当前重点支持：

| 原始字段 | 标准字段 |
| --- | --- |
| 产品名称 / 商品名称 / title | `title` |
| 产品价格 / 商品价格 / price | `price` |
| 商品链接 / productUrl / itemUrl / detailUrl | `productUrl` |
| 图片地址 / 主图 / imageUrl / picUrl | `imageUrl` |
| 店铺名称 / shopName / storeName | `shopName` |
| 商品id / 商品ID / productId / itemId / id | `externalId` 候选来源 |
| 关键词 / keyword | `rawPayload.keyword` |
| 地理位置 / 发货地 / location | `rawPayload.geoLocation` |
| 付款人数 / 销量 | `rawPayload.paidCountText` |
| 当前页面网址 | `rawPayload.currentPageUrl` |
| 当前时间 / 采集时间 | `rawPayload.capturedAt` |

## 4. 清洗脚本

脚本位置：

```text
scripts/normalize-octoparse-taobao.mjs
```

推荐命令：

```powershell
npm run product-pool:normalize:taobao -- `
  --file artifacts\product-pool\taobao-test-formal-sample.jsonl `
  --batch-source taobao_tmall_shoes_20260602 `
  --limit 50
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--file` / `-f` | 原始 JSONL 或 JSON 数组文件 |
| `--batch-source` | 本次导入批次名，建议包含平台、关键词、日期 |
| `--limit` | 额外生成首批文件的数量，默认 30 |
| `--brand-hint` | 强制写入品牌，例如 `PUMA`；不传则从关键词、标题、店铺名推断 |
| `--out-full` | 全量标准化 JSON 输出路径 |
| `--out-first` | 首批标准化 JSON 输出路径 |
| `--out-rejected` | 被丢弃或去重行的 JSONL 输出路径 |
| `--out-report` | 清洗统计报告输出路径 |
| `--include-original` | 把完整原始行写进 `rawPayload.original`，大批量数据不建议开启 |

清洗脚本会做：

- 解析 JSONL 或 JSON 数组。
- 识别淘宝/天猫平台。
- 从复杂跳转链接中提取商品 `id` 和 `skuId`。
- 标准化商品链接为 `item.taobao.com/item.htm?id=...` 或 `detail.tmall.com/item.htm?id=...`。
- 标准化价格为两位小数字符串。
- 补齐 `currency=CNY`、`stockStatus=unknown`。
- 生成后端导入格式 `{ batchSource, items }`。
- 丢弃缺标题、缺价格、缺商品链接、缺图片链接的数据。
- 去重。

## 5. 去重规则

当前去重键为：

```text
platform + externalId
```

也就是说：

- 同一个淘宝/天猫商品在不同页面、广告位、重复采集结果中出现多次，会被去重。
- 两个不同店铺卖同款商品，只要商品 ID 不同，不会被去重。
- 如果未来需要识别“不同店铺售卖的同款”，不能在清洗阶段硬去重，应进入后续“同款归并/商品簇”模块处理。

## 6. 验链脚本

脚本位置：

```text
scripts/verify-product-links.mjs
```

推荐命令：

```powershell
npm run product-pool:verify-links -- `
  --file samples\product-pool\generated\taobao_tmall_shoes_20260602-full.json `
  --out-valid samples\product-pool\generated\taobao_tmall_shoes_20260602-verified.json `
  --concurrency 6 `
  --timeout-ms 10000
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--file` / `-f` | 清洗后的标准商品 JSON |
| `--out-valid` | 只包含可访问商品的 JSON |
| `--out-invalid` | 不可访问商品的 JSONL |
| `--out-report` | 验链报告 JSON |
| `--limit` | 只验证前 N 条 |
| `--concurrency` | 并发请求数，默认 6 |
| `--timeout-ms` | 单个请求超时时间，默认 10000 |
| `--retries` | 失败重试次数，默认 1 |
| `--skip-product` | 跳过商品链接检测 |
| `--skip-image` | 跳过图片链接检测 |
| `--allow-non-image-content-type` | 图片链接不强制要求 `content-type=image/*` |

验链脚本会做：

- 商品链接 GET 检查，接受 2xx/3xx。
- 图片链接 GET + Range 检查，只拉取前 2048 字节，避免下载整张图。
- 图片默认要求响应 `content-type` 为 `image/*`。
- 输出 verified JSON、invalid JSONL 和统计报告。

注意：

- 验链只能证明链接在验证时可访问，不能保证未来永远可访问。
- 淘宝/天猫可能因登录态、风控、下架、地域、时间变化导致后续不可访问。
- 因此验链通过后，入库阶段仍必须把图片转存到 COS。

## 7. 入库命令

验链通过后，只导入 `verified` 文件。

```powershell
node scripts\import-product-pool.mjs `
  --file samples\product-pool\generated\taobao_tmall_shoes_20260602-verified.json `
  --base-url https://apiserver.zeabur.app `
  --env-file .env `
  --wait
```

如果是本地后端：

```powershell
node scripts\import-product-pool.mjs `
  --file samples\product-pool\generated\taobao_tmall_shoes_20260602-verified.json `
  --base-url http://localhost:3000 `
  --env-file .env `
  --wait
```

## 8. 批量策略

大批量数据不要一次性全部导入。

建议：

- 首次验证：30 条。
- 正常小批量：50 到 100 条。
- 大批量：按品牌、关键词、平台、页码拆批。

原因：

- 在线 embedding 成本较高。
- 图片下载、COS 上传、embedding 任一环节失败都可能导致单批耗时变长。
- 小批量更容易定位坏数据和坏链接。

## 9. 输出文件是否提交 GitHub

建议提交：

- 清洗脚本。
- 验链脚本。
- 使用说明文档。
- 少量可公开的样例导入 JSON。

不要提交：

- 原始爬虫大文件。
- 八爪鱼完整原始导出。
- 带登录态、cookie、token、账号信息的文件。
- `.env`。
- 本地浏览器 profile、缓存、截图、临时调试文件。

## 10. 当前边界

当前列表页数据通常没有完整 SKU、库存、款式尺码、每款每码价格。因此：

- `stockStatus` 暂时为 `unknown`。
- 款式、尺码、SKU 价格矩阵需要详情页采集器或后续手工补充。
- 不应在清洗脚本里伪造库存和 SKU 价格。

清洗脚本只做确定性数据整理；商品理解、同款归并、视觉打标、embedding 检索属于后端商品池和搜索链路。
