# Stitch 前端界面设计需求

更新时间：2026-06-03

本文档专门给 Google Stitch 使用，目标是让 Stitch 明确“要画哪些界面、每个界面有哪些按钮、每个按钮会进入什么状态”。Stitch 不需要理解整个代码仓库，只需要按本文生成一套可交给开发复刻的移动端高保真设计稿。

## 1. 给 Stitch 的任务定义

请设计一个中文 Android App，不是网页落地页，也不是后台管理系统。

产品名称：智能比价助手

产品口号：Just say the word.

一句话定位：用户拍摄或上传一双鞋，系统识别鞋款后返回多平台低价候选，并允许用户用自然语言继续筛选，例如“500以内，只看有货，不要拼多多”。

当前 MVP 只做鞋类商品。不要扩展到手机、服装、家电等泛商品。

## 3. Stitch 必须输出什么

Stitch 最终必须返回：

1. 可编辑设计稿链接，优先 Figma 或 Stitch 可编辑项目。
2. 每个页面的高清 PNG，尺寸见第 5 节。
3. `DESIGN.md`，包含颜色、字体、字号、间距、圆角、阴影、组件规则。
4. 所有设计中用到的图片、图标、背景资产。
5. 页面流程说明，说明每个按钮点击后去哪里。
6. 如果 Stitch 能导出代码，也要导出 HTML/CSS/React；代码不要求可直接运行，但要能帮助开发复刻布局和视觉。

## 4. 现有界面基础

当前 Flutter 前端已经有首版视觉和交互骨架，Stitch 必须在这个基础上优化，不要从零发明一个完全不同的 App。

现有移动端目录：

- `D:\shopping-assistant\apps\mobile-flutter\lib\main.dart`

现有方向：

- 首页是深色 AI 工具界面：黑色背景、白色点阵、紫蓝光晕、玻璃输入框、拍照入口、语音入口、提交入口。
- 搜索过渡页从“黑夜检索”过渡到“暖色结果页”。
- 结果页是暖色 + 深色玻璃面板：商品卡逐条出现，支持平台、排序、筛选、详情、支付、对比。
- 所有结果都围绕鞋类、价格、平台、库存、同款匹配度、自然语言继续筛选。

## 5. 设计尺寸

必须输出这些画板：

- 主尺寸：Android 竖屏 `393 x 852`
- 兼容尺寸：Android 小屏 `360 x 800`
- 可选展示尺寸：Android 大屏 `430 x 932`

所有文字、按钮、商品卡在 `360 x 800` 下不能溢出。

底部弹层需要按手机安全区留底部 padding，不要贴住屏幕底边。

## 6. 视觉方向

视觉命题：深夜 AI 搜索舱进入暖色购物决策页，整体是“科技、轻奢、克制、可操作”的中文移动 App。

内容计划：

- 首页负责启动查询。
- 图片页负责确认识别主体。
- 加载页负责解释系统正在做什么。
- 结果页负责帮助用户比较价格和货源。
- 弹层负责筛选、详情、支付和帮助。

交互命题：

- 首页输入框有轻微流光边框，聚焦时更亮。
- 搜索加载页有从深夜到黎明的渐变进度。
- 结果页商品卡应逐条出现，形成“正在检索平台并返回候选”的感觉。
- 底部弹层从下方滑入，背景轻微模糊。

## 7. 全局设计规则

必须遵守：

- 中文 UI 文案，不要英文占主导。
- 不要做营销 landing page。
- 不要做电商 App 的首页信息流。
- 不要出现复杂广告、活动 banner、优惠券墙。
- 不要把后台维护接口、商品池导入、embedding 重建等开发功能画进用户 App。
- 不要给用户承诺“全网最低价”。应表达为“已接入平台范围内的低价候选”或“当前候选池最低价”。
- 不要把支付做成真实支付完成页。当前支付是 MVP 占位，主要表现为“选择支付方式 / 模拟支付 / 后续接平台跳转”。

推荐风格：

- 背景：深夜黑、蓝紫、暖橙黎明、少量薄荷绿。
- 面板：玻璃拟态，透明深色，不要厚重边框。
- 商品卡：信息密度高，但层级清楚。
- 重要动作：薄荷绿、暖金、橙色。
- 平台标识：淘宝、天猫、京东、得物、拼多多、抖音使用不同色块。

## 8. 必须输出的页面清单

Stitch 必须至少输出下面 15 个 frame，frame 名必须接近这里的命名。

### SA-01 首页-默认态

页面目标：让用户立刻知道可以“拍鞋图 / 输入需求 / 语音搜索”。

必须包含：

- 顶部安全区。
- 左上角菜单按钮，点击打开历史抽屉。
- 品牌标识或机器人 Logo。
- 当前定位入口，文案可用“定位”或“当前城市”。
- 主标题：智能比价助手。
- 副文案：拍一双鞋，返回多平台低价候选。
- 大号玻璃输入框。
- 输入框内 placeholder：`说出你想找的鞋、预算和货源要求`
- 输入框底部三个圆形图标按钮：
  - 相机按钮，tooltip 含义：拍照或上传图片
  - 麦克风按钮，tooltip 含义：语音搜索
  - 向上箭头按钮，tooltip 含义：提交搜索
- 右下角可拖动的助手气泡，文案轮播示例：
  - `可以直接说出预算、尺码和想要的风格。`
  - `拍参考图、上传图片、语音描述都能开始搜索。`
  - `想收敛结果时，继续补充一句要求就行。`

视觉要求：

- 背景必须是深色，不要白底。
- 可以保留点阵、扫描光、紫蓝极光，但不要让背景抢过输入框。
- 输入框是第一视觉焦点。

### SA-02 首页-输入中/语音态

页面目标：展示用户开始输入或语音识别时的状态。

必须包含：

- 输入框内示例文字：`500以内，只看有货，优先淘宝和天猫`
- 麦克风按钮 active 态，图标可切换为声波。
- 提交按钮高亮。
- 语音提示文案：`正在听你描述...`
- Snack/Toast 状态之一：
  - `没有听到内容，可以直接输入。`
  - `当前平台暂不支持语音输入，可以先手动输入。`

### SA-03 历史抽屉

页面目标：展示已有会话和新对话入口。

必须包含：

- 右侧圆角抽屉，从左侧滑入。
- 顶部：Logo + `比价助手` + 收起按钮。
- 主按钮：`新对话`。
- 搜索框占位：`搜索历史对话`。
- 分组标题：`最近`。
- 历史条目：
  - `白色跑鞋 500 以内`
  - `通勤小白鞋对比`
  - `赛里木湖拍照穿搭`
  - `黑色板鞋有货优先`
  - `轻便徒步鞋推荐`
  - `同款运动鞋找低价`
- 底部账号区：
  - 头像字母 `L`
  - 用户名 `Luyang`
  - `本地演示账号`
  - 设置图标按钮

### SA-04 图片来源底部弹层

触发方式：点击首页相机按钮。

必须包含：

- 底部弹层，顶部拖拽条。
- 标题：`选择图片来源`
- 说明：`拍一张参考图，或者从相册上传本地图片。`
- 选项 1：`拍摄照片`
  - 副文案：`打开手机相机即时识别`
  - 图标：相机
- 选项 2：`上传本地图片`
  - 副文案：`从相册选择已有参考图`
  - 图标：图片
- 每一项右侧有进入箭头。

### SA-05 图片主体框选页

页面目标：让用户确认系统识别的鞋子主体。

必须包含：

- 全屏黑色背景。
- 用户上传的鞋图，等比 contain 居中。
- 图上有可拖动的识别框。
- 识别框外区域半透明遮罩。
- 识别框边角和边界可拖拽，白色控制点。
- 左上角关闭按钮，tooltip：`取消`。
- 标题：`调整识别主体`
- 底部玻璃说明面板：
  - `已先圈定画面中央较明显主体，可拖动整体或拖拽白色边界微调。`
- 底部按钮：
  - 次按钮：`重选图片`
  - 主按钮：`确认搜索`

设计约束：

- 框选页不要设计成裁剪编辑器的复杂工具栏。
- 只需要围绕“拖动框、确认搜索、重选图片”。

### SA-06 搜索过渡页

页面目标：让用户知道系统正在生成候选池，避免空等待。

必须包含：

- 深夜到暖色黎明的渐变背景。
- 居中 Logo。
- 主文案：`正在生成候选池`
- 副文案：`从黑夜检索到黎明结果`
- 横向进度条。
- 可以加入进度状态：
  - `正在识别鞋款`
  - `正在裁剪主体`
  - `正在生成图像向量`
  - `正在匹配多平台候选`

### SA-07 结果页-结果流式出现

页面目标：展示搜索正在进行，商品逐条出现。

必须包含：

- 顶部栏：
  - 返回按钮
  - 标题：`搜索结果`
  - 右侧机器人 Logo
- 继续收敛输入框：
  - placeholder：`继续收敛：500以内，只看有货`
  - 语音按钮
  - `提交`按钮
- 快捷条件 chips：
  - `500以内`
  - `只看有货`
  - `先看最低价`
- 鞋码需求面板：
  - 标题建议：`补充尺码后结果更稳`
  - 下拉/选择：`选择鞋码`
- 商品列表工具条：
  - `附近 当前城市`
  - `全部平台`
  - `智能排序`
  - `筛选`
- 搜索阶段面板：
  - `正在搜索淘宝`
  - `正在搜索天猫`
  - `正在搜索京东`
  - `正在搜索得物`
  - `正在搜索拼多多`
  - `正在搜索抖音`
- 至少 2 张商品卡正在出现。

### SA-08 结果页-完整结果态

必须包含：

- SA-07 的顶部栏、输入框、快捷条件、工具条。
- 智能建议区域，至少 3 张建议卡：
  - `赛里木湖打卡感`
  - `周末城市通勤`
  - `爆款同色系`
- 建议卡必须有：
  - 标题
  - 简短说明
  - 行动按钮，例如 `筛出轻便有货款`
- 商品卡列表，至少 5 条。
- 商品卡字段必须包含：
  - 商品图
  - 平台 logo/平台名
  - 标题
  - 店铺名，如有

  - 推荐理由
  - 价格，格式 `¥469`

  - 按钮：`去付款`
  - 按钮：`详情`
  - 右侧进入箭头

## 11. 状态设计要求

每个关键状态至少要有一个画面：

- 默认态：无输入。
- 输入态：已输入需求。
- 语音态：正在听。
- 图片选择态：拍照或相册。
- 框选态：可调整 bbox。
- 加载态：正在识别、裁剪、生成向量、匹配商品。
- 结果态：有多个商品候选。
- 筛选态：平台、排序、价格、品牌、库存。
- 空结果态：可放宽条件。
- 降级态：仍展示可用候选，但提示库存/来源需确认。
- 详情态：解释为什么推荐。
- 支付态：选择支付方式。

## 13. 设计验收标准

Stitch 输出的设计稿必须满足：

- 一眼能看出这是“拍鞋识物 + 多平台比价”的 App。
- 首页不是营销页，而是可以直接输入、拍照、语音的工作界面。
- 结果页不是普通商品列表，必须突出“同款匹配、平台、价格、库存、自然语言继续筛选”。
- 用户能从设计稿看懂完整路径：上传鞋图 -> 框选主体 -> 生成候选 -> 查看结果 -> 筛选 -> 看详情 -> 选择支付方式。
- 所有按钮都有明确文案或图标含义。
- 所有底部弹层都有标题、拖拽条、关闭/完成路径。
- `360 x 800` 小屏下商品卡、筛选 chip、按钮文字不溢出。
- 色彩不能只有紫蓝；结果页需要引入暖橙、薄荷绿、平台色，形成购物决策感。
- 不要输出只有一两个漂亮静态页面的稿子。必须输出完整页面清单。
