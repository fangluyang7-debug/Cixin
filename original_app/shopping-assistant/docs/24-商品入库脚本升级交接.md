# 商品入库脚本升级交接

本文档给负责采集、清洗和批量导入商品池的同伴使用。目标是确保新数据能够同时满足：

- 按品类缩小 ANN 检索范围；
- 商品图经过统一预处理后默认生成 `visual` embedding；`multimodal` embedding 只作为少量演示或后续预算充足时的可选能力；
- 京东、淘宝、天猫候选可以在 Android 端直达对应 App 的商品详情页；
- 唯品会、苏宁仍可正常入库和参与搜索，但暂不提供 App 商品详情直达。

## 1. 与旧版本相比新增的要求

### 1.1 `productUrl` 现在是商品身份来源

以前 `productUrl` 主要用于展示或回跳，现在后端会在入库时从它解析平台商品 ID，并保存到 `Product.externalId`。

因此生产数据必须提供真实、稳定、可访问的商品详情 URL，不能再使用：

- 搜索结果页 URL；
- 平台首页；
- 短链、广告跳转链或登录中转链；
- `example.com` 等占位 URL；
- 只包含 SKU 选择参数、但不能定位商品详情的 URL。

后端会优先采用 URL 中解析出的 ID。若传入的 `externalId` 与 URL ID 不一致：

- URL ID 覆盖传入的 `externalId`；
- 导入元数据出现 `external_id_replaced_by_product_url` 警告。

若 URL 无法解析 ID，但提供了旧 `externalId`，后端暂时兼容，并产生 `platform_product_id_legacy_fallback` 警告。新脚本不应依赖这个兼容分支。

### 1.2 多品类数据必须提供标准 `categoryHint`

当前标准品类：

| `categoryHint` | 含义 | 分组 |
| --- | --- | --- |
| `shoe` | 鞋 | footwear |
| `camera` | 相机 | digital |
| `headphones` | 耳机 | digital |
| `smartwatch` | 数码/智能手表 | digital |
| `phone` | 手机 | digital |
| `computer` | 电脑 | digital |
| `tablet` | 平板 | digital |
| `keyboard` | 键盘 | digital |
| `mouse` | 鼠标 | digital |
| `digital_other` | 其他数码产品 | digital |

`categoryHint` 在接口类型上仍为可选字段，但在生产批量入库中按必填处理。原因是：

- 商品会按标准品类进入对应 ANN 子池；
- 用户图初步分类后只在对应子池中搜索；
- 缺失时后端只能从标题或模型结果推断，可能把商品放入错误品类。

建议同时写入：

```json
{
  "categoryHint": "phone",
  "rawPayload": {
    "attributes": {
      "category": "phone"
    }
  }
}
```

两处值必须一致。`rawPayload.attributes.category` 可让来源标签直接通过，减少额外模型识别和误判。

### 1.3 平台枚举扩大

当前允许入库的平台值：

```text
taobao
tmall
jd
vipshop
suning
dewu
pdd
douyin
xianyu
manual
```

不要把未知平台静默改成 `manual` 后继续生产导入。脚本应记录拒绝原因，等待补充平台适配。

移动端 App 直达与商品池平台支持是两个概念：

| 平台 | 允许入库/ANN | Android App 商品详情直达 |
| --- | --- | --- |
| `jd` | 是 | 是 |
| `taobao` | 是 | 是 |
| `tmall` | 是 | 是，通过淘宝 App |
| `vipshop` | 是 | 否 |
| `suning` | 是 | 否 |
| 其他平台 | 是 | 当前否 |

### 1.4 商品主图质量要求提高

每条商品必须提供以下三种图片来源之一：

- `imageUrl`
- `localImagePath`
- `imageDataBase64` + `imageContentType`

推荐使用可长期访问的商品主图 `imageUrl`。图片应满足：

- 主体商品清晰，尽量只有一个主要商品；
- 避免拼图、详情长图、纯文字促销图和严重水印；
- 不要使用缩略图占位符或需要 Cookie 才能访问的地址；
- URL 返回真实图片内容，不能返回 HTML、验证码或 403 页面。

后端仍会执行统一图片 adapter：下载/读取图片、存储、主体标准化处理，再按当前环境变量生成 embedding。当前生产建议只生成：

- `visual`：纯图片 embedding，不混标题标签。

`multimodal` 是保留能力，表示图片加文本提示的兼容 embedding。由于真实商品量较大，双 embedding 会显著增加模型费用，当前不建议全量启用。

采集脚本不要自行生成 embedding，也不要绕过后端图片处理层。

## 2. 标准导入字段

### 2.1 生产必填

```text
platform
title
price
currency
stockStatus
productUrl
categoryHint
imageUrl | localImagePath | imageDataBase64
```

字段规则：

- `currency` 当前使用 `CNY`；
- `stockStatus` 只能是 `in_stock`、`out_of_stock`、`unknown`；
- `price` 使用可转换为数字的字符串，不带“¥”“元起”等文案；
- `platform` 必须使用标准小写枚举；
- `productUrl` 必须是详情页 URL；
- `categoryHint` 必须使用标准品类 key。

### 2.2 强烈推荐

```text
brandHint
shopName
shopType
externalId
rawPayload.attributes
```

`externalId` 推荐在脚本预检阶段从 URL 解析后写入，便于导入前去重；最终仍以后端从 URL 解析的结果为准。

`rawPayload.attributes` 建议至少提供：

```json
{
  "category": "phone",
  "brand": "Apple",
  "modelLine": "iPhone 15",
  "colorFamily": "black"
}
```

## 4. 推荐脚本流水线

脚本应按以下顺序处理，不能把爬虫原始输出直接提交给 API。

### 第一步：采集原始字段

至少采集：

```text
原始平台
商品详情 URL
商品标题
商品主图 URL
价格
库存状态
店铺
品牌
平台原始类目
```

### 第二步：标准化平台和品类

```js
const platform = normalizePlatform(raw.platform, raw.productUrl);
const categoryHint = normalizeCategory(
  raw.category,
  raw.title,
  raw.platformCategory,
);
```

无法确定平台或品类时，拒绝该条记录并写入 reject 文件，不要默认当作鞋。

### 第三步：规范化详情 URL 并解析 ID

```js
const productUrl = normalizeProductDetailUrl(platform, raw.productUrl);
const reference = parsePlatformProductReference(platform, productUrl);

if (!reference.productId) {
  reject('platform_product_id_unavailable');
}

const externalId = reference.productId;
```

脚本生成的 `externalId` 必须与 URL 解析结果一致。淘宝搜索结果中的 `skuId` 不等于商品 `item id`，不要把 `skuId` 当作 `externalId`。

### 第四步：验证商品与图片链接

必须同时验证：

```text
productUrl 可访问并仍指向对应平台商品详情
imageUrl 返回 image/* 内容
```

旧上传脚本中的：

```powershell
--skip-product
```

必须删除。现在不能只验图片。

### 第五步：按 `platform + externalId` 去重

```js
const dedupeKey = `${platform}:${externalId}`;
```

同一商品重复采集时保留字段更完整、图片更清晰、更新时间更新的一条。

### 第六步：生成标准 JSON

```json
{
  "batchSource": "digital_phone_20260606_batch_001",
  "items": [
    {
      "externalId": "100315128110",
      "platform": "jd",
      "title": "荣耀手机商品标题",
      "price": "1599.00",
      "currency": "CNY",
      "stockStatus": "in_stock",
      "shopName": "京东自营",
      "shopType": "official",
      "productUrl": "https://item.jd.com/100315128110.html",
      "imageUrl": "https://example-cdn.invalid/product-main.jpg",
      "brandHint": "荣耀",
      "categoryHint": "phone",
      "rawPayload": {
        "attributes": {
          "category": "phone",
          "brand": "荣耀",
          "modelLine": "具体型号"
        },
        "source": {
          "capturedAt": "2026-06-06T00:00:00.000Z"
        }
      }
    }
  ]
}
```

示例中的图片 URL 仅表示字段位置，实际导入必须替换为真实可访问图片。

### 第七步：小批量预检

```powershell
node scripts\import-product-pool.mjs `
  --file path\to\batch.json `
  --base-url https://apiserver.zeabur.app `
  --env-file .env `
  --out path\to\normalized.json `
  --dry-run
```

人工检查 `normalized.json`：

- `platform` 是否正确；
- `externalId` 是否等于详情 URL 中的商品 ID；
- `categoryHint` 和 `rawPayload.attributes.category` 是否一致；
- 是否仍有搜索页、短链、占位 URL；
- 图片是否是目标商品主图。

### 第八步：拆批、验链和上传

建议每批 30-50 条：

```powershell
npm run product-pool:verify-links -- `
  --file path\to\chunk.json `
  --out-valid path\to\verified.json `
  --out-invalid path\to\invalid.jsonl `
  --out-report path\to\verify-report.json `
  --concurrency 6 `
  --timeout-ms 10000 `
  --retries 1
```

注意：不要传 `--skip-product`。

```powershell
node scripts\import-product-pool.mjs `
  --file path\to\verified.json `
  --base-url https://apiserver.zeabur.app `
  --env-file .env `
  --wait `
  --wait-attempts 180 `
  --wait-interval-ms 5000 `
  --wait-transient-errors 30
```

## 5. 导入后必须检查

批次结果至少确认：

```text
status = completed | completed_with_errors
failedCount = 0
productsWithEmbeddingCount 与成功商品数一致
```

商品池统计至少确认：

```text
totalProducts 增加
searchableProducts 增加
visualProducts 增加
categoryGroups 中目标品类数量增加
```

抽查商品详情：

```text
platform
externalId
productUrl
category
brand
tagStatus
图片地址
visual embedding
```

若出现以下警告，暂停后续批次：

| 警告 | 含义 | 处理 |
| --- | --- | --- |
| `external_id_replaced_by_product_url` | 脚本 ID 与 URL ID 冲突 | 修复脚本 ID 解析 |
| `platform_product_id_unavailable` | URL 和输入都没有可用 ID | 拒绝该商品 |
| `platform_product_id_legacy_fallback` | URL 不能解析，只用了旧 ID | 换成标准详情 URL |

## 6. 禁止事项

- 不要使用旧中文仓库路径；当前仓库是 `D:\shopping-assistant`。
- 不要上传 `.env`、维护 token 或平台 Cookie。
- 不要把搜索页、首页或浏览器跳转链作为 `productUrl`。
- 不要用淘宝 `skuId` 代替商品 `id`。
- 不要缺省 `categoryHint` 后批量导入多品类数据。
- 不要跳过商品 URL 验证。
- 不要在采集脚本中生成 embedding。
- 不要因为唯品会、苏宁没有 App 直达而停止入库；它们仍是有效商品池平台。
