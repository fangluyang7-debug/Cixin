# APK 打包与免下载体验方案

本文只提供方案，不执行打包、部署或配置修改。最终采用哪条路径需要在确认后再实施。

## 1. 当前项目形态

项目当前包含两个前端入口：

- `apps/mobile-flutter/`：Flutter Android App，是当前主要体验入口。
- `apps/judge-entry-web/`：评委入口 Web 页，主要用于项目介绍、APK 下载和安装说明。

后端为：

- `services/api-server/`：NestJS API，部署到 Zeabur。
- 商品图、用户图、APK 文件等大文件建议放腾讯云 COS。

因此最自然的交付方式是：

```text
Flutter Android APK
+ Zeabur 后端 API
+ Zeabur 评委入口页
+ COS APK 下载链接
```

## 2. 方案 A：直接提供 APK 下载

这是当前最稳妥的课程交付方案。

### 2.1 流程

```text
设置线上 API 地址
-> Flutter 构建 release APK
-> 上传 APK 到 COS
-> 把下载链接写入 judge-entry-web
-> 部署评委入口页
-> 评委打开网页下载 APK
```

### 2.2 优点

- 与当前 Flutter 移动端代码最匹配。
- 能使用手机拍照、相册、系统跳转等原生能力。
- 不需要应用商店审核。
- 最适合展示“拍照识物”这类移动端体验。

### 2.3 风险

- 安卓手机需要允许安装未知来源应用。
- iPhone 不能安装 APK。
- 部分浏览器或系统会提示安装风险，需要在入口页写清楚说明。

### 2.4 适合场景

- 课程答辩或评委自测。
- 需要完整体验拍照、上传、结果展示和商品跳转。
- 目标设备以 Android 为主。

## 3. 方案 B：不用下载，提供 Web 体验页

这是“免安装”的最直接方式，但需要做一个 Web 版主链路页面。

### 3.1 可实现形态

```text
Web 页面上传图片
-> 调用同一套 NestJS API
-> 展示候选商品
-> 支持文本筛选
```

可以选择两种实现：

| 路线 | 说明 | 工作量 |
| --- | --- | --- |
| 在 `judge-entry-web` 中扩展体验页 | 复用现有 Vite Web 项目，增加上传、候选展示和筛选输入 | 中等 |
| Flutter Web | 把移动端 Flutter 编译为 Web | 中等偏高，且相机/文件体验需要额外适配 |

### 3.2 优点

- 评委打开网页即可使用，不需要安装 APK。
- Windows、macOS、Android、iPhone 浏览器都能打开。
- 更适合快速演示和备用体验。

### 3.3 风险

- Web 相机和相册权限体验不如原生 App 稳定。
- 如果复用 Flutter Web，移动端原生插件可能需要替换或降级。
- 如果重新做 Web 体验页，需要额外实现前端 UI。

### 3.4 适合场景

- 作为 APK 的备用入口。
- 评委不方便安装 APK 时，仍能体验核心链路。
- 更重视“能马上打开看效果”，不强调原生拍照体验。

## 4. 方案 C：PWA 轻应用

PWA 是 Web 体验页的增强版，用户可以“添加到桌面”，看起来接近 App。

### 4.1 流程

```text
构建 Web 体验页
-> 增加 manifest 与 service worker
-> 部署到 HTTPS 域名
-> 用户浏览器打开后可添加到桌面
```

### 4.2 优点

- 不走应用商店。
- 不需要下载 APK。
- 可在部分 Android 浏览器上接近 App 使用体验。

### 4.3 风险

- iOS 对 PWA 能力支持有限。
- 仍然依赖浏览器权限和网络环境。
- 对课程交付来说，性价比未必高于普通 Web 体验页。

## 5. 方案 D：小程序入口

文档中已预留“后续小程序入口”。理论上可做抖音小程序或微信小程序版本。

### 5.1 优点

- 用户无需安装 APK。
- 更符合国内移动端分发习惯。
- 可以复用后端 API 和商品池。

### 5.2 风险

- 需要平台账号、审核和小程序前端适配。
- 图片上传、跳转外部商品页、API 域名白名单都可能受平台规则限制。
- 当前时间成本较高，不建议作为本次最小交付主路径。

## 6. 推荐决策

当前建议采用“两层交付”：

| 层级 | 推荐方案 | 作用 |
| --- | --- | --- |
| 主入口 | APK 下载 | 展示完整移动端能力，适合拍照识物主体验 |
| 备用入口 | Web 体验页 | 不方便安装时仍可体验上传图片和候选召回 |

暂不建议把小程序作为本轮主要交付，因为审核和平台限制会增加不确定性。

## 7. APK 打包实施时需要做的事

确认采用 APK 路线后，再执行以下事项：

1. 确认 Zeabur 后端已部署并能公网访问。
2. 确认 Flutter App 的 API 地址指向线上后端。
3. 使用 release 模式打包 APK。
4. 在真实安卓设备上安装测试。
5. 上传 APK 到 COS。
6. 设置 `PUBLIC_APK_DOWNLOAD_URL`。
7. 重新部署 `judge-entry-web`。
8. 从入口页点击下载并重新安装验证。

## 8. 免下载体验实施时需要做的事

如果确认要做 Web 免下载体验，建议优先扩展 `apps/judge-entry-web`，而不是立刻迁移 Flutter Web。

最小功能：

- 图片上传。
- 创建 session。
- 轮询或订阅搜索进度。
- 展示候选商品卡。
- 文本输入继续筛选。
- 打开商品详情页。

这样可以复用同一套后端 API，并且不会影响当前 Flutter App。
