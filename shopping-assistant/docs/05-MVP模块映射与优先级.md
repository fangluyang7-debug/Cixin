# MVP 模块映射与优先级（V0）

## 1. 文档目的

本文档用于把已经确定的模块体系，正式映射到首版 MVP 范围中，回答以下问题：

- 哪些模块是首版闭环成立的必要条件
- 哪些模块应进入首版，但可以用简化方案落地
- 哪些模块只在当前阶段保留接口和结构，不进入首版验收
- 首版开发时，各模块的实现顺序应如何安排

这里的重点不是完整产品怎么做，而是首版到底做到什么程度才算边界清楚、优先级合理。

## 2. 优先级分层规则

当前建议把模块优先级分成 3 层。

### 2.1 P0：首版闭环必做

满足以下任一条件的模块，应进入 P0：

- 缺失后，`拍照 -> 多平台结果 -> 自然语言多轮收敛` 无法成立
- 缺失后，首版无法满足 `01-MVP定义.md` 中的最小闭环
- 缺失后，系统虽然能展示局部功能，但不能形成完整查询过程

### 2.2 P1：首版建议落地，但允许简化

满足以下条件的模块，应进入 P1：

- 对比赛演示质量和产品完整感很重要
- 能明显增强用户决策体验
- 但即使简化，首版闭环仍然成立

P1 不等于“不做”，而是允许用较轻版本先落地。

### 2.3 P2：先留接口和结构，不进入首版验收

满足以下条件的模块，应进入 P2：

- 属于完整产品的重要能力
- 当前不是首版闭环的必要条件
- 可以先在数据结构、模块边界和接口层预留扩展空间

## 3. 当前 MVP 映射总览

基于现有 `01/03/04` 三份文档，当前建议的 MVP 模块映射如下：

### 3.1 P0：首版闭环必做模块

1. 用户输入与会话启动模块
2. 商品理解模块
3. 跨平台检索与聚合模块
4. 结果标准化与候选池模块
5. 结果筛选与收敛模块
6. 会话与状态保持模块

### 3.2 P1：首版建议落地，可简化实现

1. 智能建议模块
2. 决策辅助模块
3. 商品详情模块
4. 缓存、降级与恢复模块

### 3.3 P2：先留接口和结构，不进入首版验收

1. 历史价格模块
2. 用户记忆与偏好模块
3. 配送时效与地理位置模块

## 4. 模块逐项映射说明

### 4.1 用户输入与会话启动模块

**优先级**

P0

**进入 MVP 的原因**

- 没有它，整条查询链路无法开始
- 它直接决定是否能完成拍照或上传启动查询

**首版落地要求**

- 必须稳定支持拍照或上传发起查询
- 必须能创建会话并把后续操作挂到同一轮查询上

### 4.2 商品理解模块

**优先级**

P0

**进入 MVP 的原因**

- 没有商品画像，就无法支撑后续跨平台搜索
- 它是整个“拍照识物”能力的核心

**首版落地要求**

- 能对鞋类商品形成基础商品画像
- 至少能输出支撑搜索的关键属性

### 4.3 跨平台检索与聚合模块

**优先级**

P0

**进入 MVP 的原因**

- 没有它，就没有“比价”本身
- 多平台候选结果是首版闭环的直接目标之一

**首版落地要求**

- 能基于商品画像返回多平台候选结果
- 至少返回价格、平台、货源基础信息

### 4.4 结果标准化与候选池模块

**优先级**

P0

**进入 MVP 的原因**

- 没有统一候选池，就无法支撑后续筛选和多轮更新
- 多平台结果若不统一，前台无法稳定比较

**首版落地要求**

- 必须建立当前会话的候选池
- 必须支持后续筛选与重排

### 4.5 结果筛选与收敛模块

**优先级**

P0

**进入 MVP 的原因**

- 用户的自然语言追加要求直接依赖它
- 多轮连续交互是否成立，核心看这个模块

**首版落地要求**

- 至少能把自然语言转成一组有效筛选条件
- 至少能在已有候选池上进行过滤、重排或触发补充检索

### 4.6 会话与状态保持模块

**优先级**

P0

**进入 MVP 的原因**

- 首版明确要求“多轮并具有连续性”
- 如果没有会话状态保持，多轮交互会退化成一次次重新开始

**首版落地要求**

- 必须保留当前识别结果、筛选条件和候选池状态
- 必须保证同一会话中的连续追问有效

### 4.7 智能建议模块

**优先级**

P1

**进入首版但不列入 P0 的原因**

- 它能明显增强产品辨识度和比赛观感
- 但即使只先实现拍照、结果展示和自然语言筛选，最小闭环仍然成立

**首版建议落地方式**

- 可以先做规则驱动的建议卡片
- 可以先做有限数量的主动推荐结论
- 先不追求复杂个性化建议体系

### 4.8 决策辅助模块

**优先级**

P1

**进入首版但不列入 P0 的原因**

- 它能提升“为什么该选这个结果”的表达能力
- 但首版最小闭环成立并不依赖复杂决策解释

**首版建议落地方式**

- 先做基础比较信息汇总
- 先输出简短推荐理由或标签
- 先不追求复杂评分体系

### 4.9 商品详情模块

**优先级**

P1

**进入首版但不列入 P0 的原因**

- 它有助于演示完整决策过程
- 但 MVP 的成立核心仍然是“查到结果并能多轮收敛”

**首版建议落地方式**

- 可先做轻量详情页或弹层
- 先承载价格、平台、货源、购买链接和基础推荐理由

### 4.10 缓存、降级与恢复模块

**优先级**

P1

**进入首版但不列入 P0 的原因**

- 它不决定产品逻辑是否成立
- 但对比赛演示稳定性和抗失败能力很重要

**首版建议落地方式**

- 至少准备 mock 降级链路
- 至少准备最近一次结果缓存或兜底结果
- 先不追求完整缓存体系

### 4.11 历史价格模块

**优先级**

P2

**暂不进入首版验收的原因**

- 它是完整产品的重要增强项
- 但不属于当前用户已经确认的 MVP 必解问题

**当前阶段要求**

- 在数据对象和模块边界中保留接入位置
- 不要求首版必须交付真实历史价格能力

### 4.12 用户记忆与偏好模块

**优先级**

P2

**暂不进入首版验收的原因**

- 它能明显增强长期体验
- 但首版 MVP 更关注一次会话内的闭环成立

**当前阶段要求**

- 在数据对象中保留用户资料、偏好和确认结果
- 首版可不做完整长期记忆产品能力

### 4.13 配送时效与地理位置模块

**优先级**

P2

**暂不进入首版验收的原因**

- 它属于附加参考能力
- 当前 MVP 的重点不是“更快送达”，而是“更快找到符合要求的低价同款”

**当前阶段要求**

- 在筛选条件和决策辅助对象中预留时效相关位置
- 首版可不实现真实送达时间估算

## 5. 当前 MVP 最小模块闭环

如果只看首版是否成立，当前建议的最小模块闭环是：

`用户输入与会话启动`
-> `商品理解`
-> `跨平台检索与聚合`
-> `结果标准化与候选池`
-> `结果筛选与收敛`
-> `会话与状态保持`

这 6 个模块必须一起成立。

如果只缺其中任意一个，当前 MVP 定义中的闭环都会断掉。

## 6. 当前 MVP 推荐演示增强层

如果目的是让首版不仅能跑，还能更像一个完整产品，当前建议加入的首版增强层是：

`智能建议`
-> `决策辅助`
-> `商品详情`
-> `缓存、降级与恢复`

这一层不改变 MVP 是否成立，但会明显影响：

- 演示流畅度
- 用户决策感
- 产品完整度
- 现场抗风险能力

## 7. 当前阶段的开发顺序建议

为了避免首版一开始就陷入非核心功能，当前建议按下面顺序推进：

### 第一阶段：先打通 P0 主链路

1. 用户输入与会话启动模块
2. 商品理解模块
3. 跨平台检索与聚合模块
4. 结果标准化与候选池模块
5. 会话与状态保持模块
6. 结果筛选与收敛模块

### 第二阶段：补强首版可演示性

1. 智能建议模块
2. 决策辅助模块
3. 商品详情模块
4. 缓存、降级与恢复模块

### 第三阶段：继续向完整产品扩展

1. 历史价格模块
2. 用户记忆与偏好模块
3. 配送时效与地理位置模块

## 8. 当前文档结论

到这一步为止，当前项目已经形成了完整的首版优先级结构：

- `01` 定义了 MVP 闭环目标
- `03` 定义了模块职责边界
- `04` 定义了模块输入输出和核心对象
- `05` 把所有模块映射到了首版优先级体系中
