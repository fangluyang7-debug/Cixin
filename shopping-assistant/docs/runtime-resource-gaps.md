# Runtime 真实资源状态与阻断项

更新时间：2026-09-15

这份清单记录当前仓库能够证明的资源，以及还不能证明的资源。没有完成真实探测、授权或基准测试的能力，不会被 Scheduler 当作可用执行器。

## 已落地且可以验证的部分

- `ToolDescriptor`、`TaskIntent`、`TaskGraph`、`PlatformProfile`、`RuntimeState`、`ExecutionPlan` 和 `TelemetryRecord` 协议。
- Shopping Plugin 的 7 个业务工具注册。
- 任务依赖图的缺失依赖、重复 ID 和循环依赖检查。
- 隐私、位置、内存、模型支持、后端可用性、P95 时延、质量和能耗硬约束。
- 基于真实 Telemetry 样本的 P50/P95、质量、能耗和可靠性评分，以及切换滞回。
- 当前 Node 主机的 CPU 核数、总内存、空闲内存和 CPU 使用率读取。
- 缺少真实数据时返回 `blocked`，而不是选择一个经验后端。
- 业务可注册任意操作与模板，核心默认无购物操作；购物演示另行注册四类规则。Provider v1 含允许操作集合、版本、优先级、隐私与解释，非法/超时/低置信度结果回退。
- nominal/warning/critical/unknown 分级；普通高负载不单独阻断。warning 计划串行化并重算时限，允许的轻量候选获得相对评分优待。
- 可注入 PlatformAdapter 列表；Linux 本地保护辅助组件先停止自建进程组再回调上报，API 验证令牌与当前 executionId。该组件尚未接入真实购物/板端执行器。
- Run 检查点元数据与 Telemetry 通过 runId/executionId/checkpointId 关联，提交前补充资源和时限检查。
- 新鲜观测的短期趋势外推、红线与未知数据标记；候选模型变体、依赖链时限和并行内存检查。
- `GuardedExecutionService` 可取消 Handler/阶段检查点协议，运行中保护与失败状态；单元测试覆盖取消、恢复失败、质量失败和任务能耗超限回退。当前未注册购物业务 Handler。
- Telemetry 的输入校验、执行身份核对和 `executionId` 幂等/冲突检测，避免非法或重复样本直接影响 P95 与可靠性。

## 当前明确缺失的资源

### 云端基础设施

- 云端数据库托管平台、实例地址、数据库名称、账号、密码和 TLS 配置。
- 对象存储平台、区域、Endpoint、Bucket、访问密钥和生命周期策略。
- 云端 API 网关或服务部署地址，以及网络、域名和证书配置。
- Agent Planner 所需的大模型平台、模型名称、API 地址、密钥、配额和超时策略。
- 视觉模型、聊天模型、Embedding 模型的真实供应商、模型名称、密钥和维度。
- 视觉、聊天、Embedding 供应商的真实健康检查和模型探测协议。

`CloudPlatformAdapterService` 当前会把云端执行器保持为不可用，即使环境变量写入了 URL、Key 和 Model。配置本身不是健康检查、模型探测或能力证明；必须先实现供应商级适配器并完成真实请求验证。

### 授权数据源

- 淘宝、抖音电商、拼多多、得物、京东等平台的正式授权 API、调用范围、限流和合规凭据。
- 商品池的确认来源、抓取/导入授权、数据更新时间和失效策略。
- 实时价格、库存、商品链接和历史价格的可验证数据源。

未提供上述授权时，不能把商品池样例或本地测试数据宣称为实时平台结果，也不能启用 marketplace 执行器。

### HarmonyOS、CIX P1 与模型运行时

- HarmonyOS/CIX P1 真机或开发板、系统版本、连接方式和 SDK。
- CPU/GPU/NPU 的真实设备信息与统一适配器实现。
- NeuralONE、MindSpore Lite 或其他实际采用的模型运行时版本。
- GPU/NPU 支持的模型文件、算子支持矩阵、INT8/FP16 能力、输入尺寸和 CPU fallback 结果。
- 模型加载、推理、取消、检查点和执行结果回传接口。

Runtime 已提供 CIX P1 心跳协议和通用 Linux 采集代理；没有新鲜心跳时 HarmonyOS/CIX P1 适配器仍返回 `*_DEVICE_ADAPTER_NOT_CONNECTED`，不会伪造硬件能力。真实 NPU SDK、模型运行时和推理执行接口仍待目标板验证。

### 动态硬件与网络监测

- CIX 厂商 GPU/NPU 利用率、功耗域和算子队列探针。
- 热降频标志、精确能耗以及芯片特定传感器映射。
- 每网口/每外设状态、网络抖动/丢包主动探测和协议会话状态。
- 运行时活动任务计数器以及跨阶段取消/恢复信号。

`tools/cix-runtime-agent` 已能从 Linux `/proc`、`/sys` 采 CPU 总/每核利用率、频率、内存、温度、风扇、网卡吞吐、磁盘吞吐/空间和 uptime，并允许厂商 SDK 通过 JSON 探针文件补充其余字段。当前主机适配器仍只证明 CPU、内存和 CPU 使用率；所有未观测指标都以不可用状态返回，不会填入默认值。

### 真实性能档案

每个工具、执行器和模型组合都需要在目标设备上采集至少配置的最小样本数，并记录：

- P50/P95 延迟。
- 峰值内存。
- 能耗和温升。
- 任务质量指标，例如识别置信度、Recall@K 或相似度。
- 失败率、fallback 次数和成功率。
- 输入尺寸、模型版本、运行时版本和设备标识。

当前性能档案只在进程内由 Telemetry 累积，没有持久化基准库；没有样本的候选会被硬性淘汰。

## 仍未实现的运行能力

- 训练好的端侧调度模型、可证实的分类/路由评估及其宿主 Provider 部署；当前规则模板不是模型。
- 购物七工具的受保护执行 Handler。新执行接口只接受已注册、可取消且可恢复的 Handler；旧购物图片搜索链路仍自行执行，不受这个保护服务控制。
- 跨进程/设备的 checkpoint 和全局事务回滚，实际模型变体部署、降级后的重试和迁移。
- 持久化 Telemetry、跨进程性能学习和审计日志。
- Provider-specific Cloud、HarmonyOS 和 CIX P1 Platform Adapter。
- 独立发布的 Runtime SDK/npm 包、语义化版本兼容测试，以及通用本机 sidecar IPC 适配器。

这些能力缺失时，API 会返回阻断原因；不能用固定 CPU/GPU/NPU 链条替代。

## 处理顺序

1. 确认云端数据库、对象存储、模型 API 和授权电商 API。
2. 提供目标设备、SDK、模型文件和运行时版本。
3. 实现并验证各平台的静态能力、模型能力和动态状态采集。
4. 在目标设备上采集性能样本，再启用 Scheduler 评分和滞回。
5. 将购物工具逐个绑定真实 Handler，标记可回退的应用资源；采集分类标签，再以可插拔 Provider 评估端侧决策模型。

在目标设备、实测样本和 Handler 齐备前，Cixin 的购物端到端执行仍以旧业务链路为主。新增受保护路径是可测试的通用调度初版，不代表现有购物链路或 CIX P1 NPU 已完成接入。
