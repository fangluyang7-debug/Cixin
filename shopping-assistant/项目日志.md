### 实现中的修正

- 不把“实时性高”机械等同于端侧，也不把“复杂”机械等同于云端。最终执行位置仍由模型能力、样本、隐私、质量及预算裁决。
- CPU 利用率 96% 不再单独触发拒绝；旧 CPU 阈值配置仅作为告警阈值兼容别名。
- 低电量需要结合外部供电、任务可中断性及实测能耗，不再所有任务一刀切停止。
- Node 定时监控之外增加提交前检查；短阶段跨过截止时间也不会提交。守护执行路径按串行实际能力检查预算。
- 终端 workerStopped 是停止确认，不是恢复完成；仍等 Handler 结束再 restore。守护只管理自己启动的进程，不操作其他应用。
- 保留模板节点原有 checkpointPolicy，避免把声明不能检查点恢复的任务改成可恢复。
- 并行累计内存超限时先尝试串行，再按新完成时间校验预算；运行期保护继续使用规划时的实测能耗估计。critical 与 warning 并存时不输出“允许运行”的矛盾建议。

### 记录方式与未完成项

RuntimeRun 保存图、计划、候选评分/预测、最多 200 条阶段时间线、输出、保护状态和检查点关联。Telemetry 保存真实执行的耗时、峰值内存、可选质量/能耗、成功/回退标记与关联元数据；没有完整实测的异常/中止只保存运行状态，不伪造资源样本。事件总线保留最近 200 条事件。检查点真实快照由 Handler 持有，不写入通用 Run。

本轮未加入数据库/文件持久化；重启恢复、失败样本全面采集、模型训练数据治理、跨进程恢复、真实端侧模型评估、CIX 真机保护时延和收益对照均未完成。功耗/DMA 等部分探针可以上报，但没有全部建立预测方程。API 和 SDK 产品化、多租户权限隔离也不是本轮已交付能力。
